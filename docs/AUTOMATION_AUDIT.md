# Автоматика MTProxy Pushok · v1.09

| Этап | Поведение |
|---|---|
| Новая кампания | Транзакционная очередь уведомлений администраторам и операторам |
| Модерация содержания | Решение администратора/оператора; отправляется уведомление |
| Stars | Автоматическая проверка и подтверждение сервером, защита от дублей |
| СБП | Проверка провайдером, webhook и фоновая сверка; нужны действующие реквизиты и включённый worker |
| Назначение периода | Фоновый подбор подготовленного узла с привязкой тега и свободного периода после одобрения и оплаты |
| Запуск | Агент применяет подготовленный тег, проверяет процесс и доступность прокси, затем активирует кампанию |
| Завершение | После успешного снятия/смены тега агент завершает истёкшую автоматически запущенную кампанию |
| Ошибка агента/сети | Повторный цикл; успешный запуск/завершение не подменяются таймером |
| Отображение статусов | Автообновление каждые 20 секунд в основных разделах, без сброса редактируемой формы |
| История | События автоматического назначения, запуска и завершения отображаются в отчёте |

## Что требует первичной настройки или решения

- Получение/регистрация тега в Telegram и привязка тега каждого рекламируемого канала к конкретному узлу. Проект не получает тег произвольного канала сам. Без привязки автоподбор оставляет новую кампанию в ожидании подготовки, чтобы не назначать заведомо неработающий запуск. Ранее назначенные вручную периоды требуют действующей привязки.
- Установка агента на поддерживаемом узле official_mtproxy; текущий агент не применяет настройки Docker/Telemt автоматически.
- Реквизиты и ключи СБП, включение приёма платежей. Спорные суммы, возвраты и неясный результат создания платежа остаются исключениями для сверки; их нельзя считать успешной оплатой автоматически.
- Решение модератора о содержании канала. Это отдельный этап, а не ручной запуск оплаченной кампании.
- Ручная проверка показа/скриншот — необязательная диагностика. Применение тега не является независимой статистикой показов Telegram.
- Восстановление резервной копии и проверка реальных возвратов — приёмочные проверки, не условия запуска каждой кампании.

Управление администраторами: «Управление → Пользователи и награды → Права пользователей». Назначение по точному Telegram ID, после первого входа пользователя в кабинет. У новых администраторов/операторов включается подписка на модерацию; для доставки они должны запустить Telegram-бота. Самоснятие прав и удаление последнего администратора запрещены. Изменение роли записывается в аудит и завершает старые сессии пользователя.

Исторические красные запуски CI сохраняются в GitHub как журнал. Исправление проверяется новым запуском, а не удалением старых результатов.
