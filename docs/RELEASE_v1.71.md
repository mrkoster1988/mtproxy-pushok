# v1.71 — Актуальность статуса автосоздания

После включения автосоздания заголовок показывал «Включено», а последний отчёт агента ещё показывал «Выключено». Проверка возраста отчёта не учитывала изменение настроек между проходами агента.

Теперь хостовый агент и диагностика записывают идентификатор проверенной версии настроек. API сравнивает его с текущей сохранённой версией. Даже отчёт, записанный позднее сохранения, остаётся предыдущим, если проход агента использовал старую версию.

В кабинете:

- Заголовок отражает сохранённое разрешение. После его выключения статус явно сообщает, что автосоздание выключено в настройках.
- После изменения настроек показывается «Ожидаем проверку новых настроек», пока агент не пришлёт подходящий отчёт.
- Предыдущая диагностика не подтверждает новые разрешения, порты и лимиты. Эти строки ожидают нового отчёта; остальные результаты помечаются как проверенные ранее.
- Старые отчёты без версии настроек не подтверждают текущую политику. Проверка срока давности также сохраняется.
- Изменение разрешения ИИ отдельно учитывается при показе готовности, даже если параметры автосоздания не редактировались.

Настройки и выбранные лимиты сохраняются. Миграций нет. После штатного обновления проекта и хостового агента очередной проход обновит отчёт; кнопка «Обновить» загрузит его в кабинет. Таймер обычно запускается через 5 минут после завершения предыдущего прохода.

Проверки воспроизводят включение после старого `disabled`, позднюю запись старого отчёта, получение новой версии, отключение и совместимость с отчётом без версии. Браузерный сценарий работает с настоящими API и PostgreSQL. Проверка публикации отчёта ограничивает метаданные корректным UUID. Живое создание прокси или показ спонсора этими тестами не подтверждаются.
