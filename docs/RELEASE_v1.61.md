# v1.61 — подключение ИИ из кабинета

Администратор подключает OpenAI для подсказок тематики канала в **Профиль → Настройки → Система → ИИ · Тематика каналов**. Доступны ключ API, модель, проверка, включение/выключение и удаление ключа. Поле тематики при создании кампании остаётся необязательным; ручной выбор имеет приоритет.

## Подключение

1. Установите v1.61 через «Профиль → Версия и обновления».
2. Откройте карточку ИИ и введите ключ своего OpenAI API-проекта. По умолчанию используется `gpt-4.1-mini`; можно указать другую модель, совместимую с Chat Completions и Structured Outputs.
3. «Проверить» выполняет короткий запрос на учебном примере, но не сохраняет и не включает ИИ.
4. Включите переключатель и нажмите «Сохранить». Сервер повторно проверит ключ, модель и формат ответа перед включением. Перезапуск не требуется.

Запросы, включая проверки, расходуют средства API-проекта. Настройки не содержат готового ключа. Если ключ отсутствует, провайдер недоступен или исчерпан лимит, работают существующие подсказки по ключевым словам. Создание кампании и ручной выбор тематики не блокируются.

## Данные и хранение

- OpenAI получает только название, описание и до 8 доступных публичных текстовых публикаций выбранного канала. Данные из профилей пользователей (включая подтверждённый телефон), платежи и закрытые переписки не передаются. Контактные сведения, опубликованные в самом канале, могут присутствовать в анализируемом тексте.
- Ответ модели ограничен каталогом тематик. Подсказка с недостаточной уверенностью оставляет поле пустым. Содержание канала обрабатывается как недоверенные данные.
- Ключ находится в `.control/channel-ai-private.json` с правами `0600`, как существующие приватные настройки СБП. Это закрытый файл, а не шифрование содержимого; доступ администратора VPS и резервные копии требуют такой же защиты, как `.env`.
- API не возвращает ключ, даже частично. Ошибки валидации не включают исходные поля запроса. В аудите сохраняются только факт изменения, включение и признак замены ключа.
- Файл включён в существующий механизм приватного резервного копирования и восстановления. Обычное обновление приложения его сохраняет.
- До первого сохранения поддерживаются `CHANNEL_TOPIC_AI_ENABLED`, `CHANNEL_TOPIC_AI_API_KEY`, `CHANNEL_TOPIC_AI_MODEL` из `.env`. После сохранения настройки кабинета имеют приоритет. Удаление ключа отключает его использование, включая резервный ключ из `.env`; сам файл `.env` не редактируется. Повреждённая конфигурация отключает ИИ, без скрытого возврата к `.env`.

## Надёжность

- Рекламодатель и оператор не могут читать или менять настройки ИИ; проверка подключения тоже доступна только администратору.
- Ошибка проверки сохраняет прежнюю конфигурацию. Отключение и удаление доступны без обращения к OpenAI.
- Ревизия настроек защищает от перезаписи изменений другого администратора. Поздние ответы не возвращают форму после выхода из аккаунта.
- Анализ запускается только при открытой форме создания кампании, а не при загрузке скрытых элементов других страниц.
- Сохраняются кэш подсказок на 10 минут, ограничение 60 запросов OpenAI в час на процесс API и фиксированный адрес провайдера без перенаправлений. Для административной проверки — максимум 6 попыток в минуту на процесс и одна проверка одновременно.
- Для сетевых обращений заданы тайм-ауты и ограничения размера ответа. Ошибки ключа, модели, лимитов и соединения показываются в карточке понятным текстом.

## Проверки

Тесты покрывают права, отсутствие ключа в ответах/ошибках/аудите, файл `0600`, замену и удаление ключа, приоритет над `.env`, ошибки провайдера, конфликты ревизий и лимит проверок. Браузерный сценарий использует настоящий API и отдельную тестовую БД; подменяется только ответ OpenAI. Проверяются размеры 320, 390, 768 и 1280 px, сохранение, очистка поля ключа и выход во время запроса.

Подключение реального API-проекта и работа на VPS проверяются после ввода ключа владельцем; тесты не обращаются к платному OpenAI API.
