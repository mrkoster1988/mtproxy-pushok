# Реальные страницы кабинета

Рабочая реализация концептов из архива `mtproxy_pushok_13_screens` находится в
`api/web/index.html`, `pages.js`, `app.js` и `styles.css`. После Telegram-входа
открывается светлый кабинет с боковым меню. Сервер по-прежнему отдаёт `/`;
маршруты после `#` работают без дополнительной настройки reverse proxy.

| Экран | Маршрут | Источник и действия |
| --- | --- | --- |
| Главная | `/#/dashboard` | Собственные `/campaigns`, `/channels`; показатели по статусам без фиктивных расходов или показов |
| Мои каналы | `/#/channels` | GET/POST `/channels`; публичная ссылка t.me и название |
| Создание | `/#/create` | GET `/tariffs`, POST `/campaigns`; создаёт черновик, затем открывает карточку |
| Кампании | `/#/campaigns` | Поиск и фильтр полученного списка `/campaigns` |
| Карточка | `/#/campaign/{id}` | Собственная заявка, исправления, submit, бронь и ручные проверки |
| Оплата | `/#/payments` и `/#/payments/{id}` | Только одобренные заявки; `/payment-instructions`, `/payment-proofs`, `/slot-hold` |
| Календарь | `/#/calendar` | `/availability`; тот же выбор тарифа, даты и времени, что в форме создания |
| Отчёты | `/#/reports` | Приватные `/campaigns/{id}/report` и `/report.csv` |
| Модерация | `/#/moderation` | `/operator/campaigns`; существующие действия исправления, одобрения, оплаты, расписания и наблюдений |
| Спонсоры и узлы | `/#/sponsors` | Реестр `/operator/proxy-nodes`; администратору доступны добавление, план, пауза и `/sponsor-registration` |
| Настройки | `/#/settings` | Администратор: платежи, изменение тарифа, готовность системы и ядра |
| Помощь | `/#/help` | Инструкции, раскрывающиеся ответы, повторное включение стартовой инструкции |
| Бот | `/#/bot` | Имя из `/public-config`; ссылка не показывается, если имя не настроено |

Все пути API имеют префикс `/api/v1`. Чужие кампании не добавляются в список и
не открываются по подставленному ID. Операторские страницы скрыты от рекламодателя,
а сервер независимо проверяет права. Истечение сессии очищает клиентские данные
и возвращает форму входа. Ошибка API не заменяется успешным статусом.

## Отличия от иллюстраций

Примерные числа и даты из изображений не переносятся в продукт. API не сообщает
подтверждённый статус канала как отдельного объекта, поэтому такого бейджа нет.
Фактические расходы, показы Telegram, свободные узлы «прямо сейчас» и мнимые
уведомления не выводятся без источника. Окончание определяется данными заявки.
Цены отображаются с копейками, если они заданы в тарифе.

Код веб-счёта СБП и серверной сверки добавлен, но выключен до настройки и приёмки (см. SBP_WEB_CHECKOUT.md). Stars оформляются в боте только при включении
сервером; ссылка на бот не подтверждает готовность оплаты. Реквизиты и чек
относятся к существующему ручному сценарию. Сохранение спонсорского тега и плана
движка не меняет конфигурацию прокси и не выполняет Set promotion.

Не добавлены формы для несуществующих серверных настроек правил и уведомлений.
Цена и длительность меняются через действующую форму тарифа. В отдельной карточке
сохраняются существующие действия отчётов и наблюдений; в очереди — все действия
оператора, включая обязательные комментарии и подтверждения.

## Проверка

`scripts/check_cabinet_pages.py` использует настоящий FastAPI и PostgreSQL.
Он требует явного разрешения `PUSHOK_TEST_DB_ALLOWED=1` и тестового
`TEST_ADMIN_DSN`, создаёт отдельную случайную базу и удаляет её после запуска.
Сессии создаются только внутри этой базы, обход авторизации в API не добавляется.
Внешние запросы браузера запрещены. Настоящие платежи, Telegram и VPS не участвуют.

```bash
python -m pip install -r api/requirements-dev.txt playwright==1.56.0
python -m playwright install --with-deps chromium
python scripts/check_cabinet_pages.py --out .build/cabinet-pages
```

Сценарий проверяет создание и исправление канала, черновик и отправку,
модерацию, бронь и отмену, чек и повторную подачу, проверку оплаты, расписание,
отрицательное и положительное наблюдение, завершение, отчёты и CSV, цену тарифа,
роли и чужие данные, поиск, историю навигации и истечение сессии. Активный период
переставляется только в тестовой базе; наблюдения не доказывают реальный показ.
Проверяются ширины 320, 390 и 768 px, создаются отдельные снимки экранов.

Задание `cabinet-preview` в GitHub Actions запускает этот сценарий и сохраняет
архив `pushok-cabinet-pages`. При ошибке прикладываются снимки места сбоя.
До успешного выполнения задания и осмотра изображений визуальная приёмка не
подтверждена. Архив содержит только изолированные тестовые данные.

Для предварительных изображений без PostgreSQL сохранён отдельный сценарий
`scripts/render_cabinet_previews.py` с синтетическим API. Он не проверяет записи
в базе и не заменяет интеграционную проверку.
