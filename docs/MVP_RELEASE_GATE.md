# MTProxy Pushok — приёмка основы MVP

**Feature freeze с изменением приоритета владельцем.** Новые движки, телеметрию и автоматизацию спонсоров не добавляем, но Telegram Stars и СБП объявлены обязательными для коммерческого MVP и должны пройти отдельную приёмку (см. [PAYMENTS_STARS_SBP.md](PAYMENTS_STARS_SBP.md)). Статус на 13 ноября 2026: **НЕ ПРИНЯТ**.

## Границы законченного MVP

Вход Telegram, заявка рекламодателя с каналом и тарифом «1 день — 300 ₽», модерация, ручное подтверждение оплаты по чеку, календарь и назначение слота, регистрация спонсорского тега через @MTProxyBot, его *ручное* применение и снятие оператором, ручной журнал наблюдений, завершение и отчёт JSON/CSV. Отдельные роли, HTTPS, приватное хранение доказательств и восстановление БД обязательны.

**Обязательно до коммерческого запуска:** Stars и СБП, серверное подтверждение, повторы и сверка, сценарий возврата. Для каждого провайдера нужны отдельные живые доказательства. Автосмена тегов и неподтверждённые метрики Telegram не объявляются готовыми; публичный кабинет не открывается автоматически.

## Безопасный порядок при появлении тестового VPS

1. Убедиться, что сервер **не содержит боевых сервисов**. Сделать снимок VPS, не использовать домены работающих магазинов и отдельные секреты.
2. В отдельном клоне репозитория запустить `python3 scripts/verify_release.py --mode offline`. Сохранить вывод с SHA коммита без токенов.
3. Проверить `bash scripts/smoke.sh` на тестовом Docker/Compose; он создаёт и удаляет временные ресурсы, убедиться в их изоляции.
4. Запустить `bash setup.sh --plan`, просмотреть предложенные параметры. Реальную установку — после оценки плана и отдельно от действующего магазина. После настройки выполнить `bash scripts/staging_preflight.sh` под владельцем `.env`; [описание проверки](STAGING_PREFLIGHT.md).
5. Использовать реальный Telegram-клиент на независимой учётной записи. Проверить и зафиксировать время показа/отсутствия канала; **скриншоты сами по себе не доказывают Telegram API impressions**.
6. Пройти полную сделку, проверить резервную копию и восстановление, сохранность секретов и отзыв доступа оператора.
7. Решение о приватном пилоте принимать только при доказательствах по всем пунктам. Публичная публикация — отдельное разрешение.

## Контракт завершающего запроса

`POST /api/v1/operator/campaigns/{id}/complete`, обязательное JSON-тело:

```json
{"tag_removed_confirmed":true,"verification_method":"separate_unsubscribed_client"}
```

Без тела/подтверждения — HTTP 422; если размещение не active — HTTP 409; несуществующая заявка — 404. Audit фиксирует **сообщение оператора**, но API сам не выключает MTProxy и не удостоверяет Telegram.

## Решение о выпуске

Сейчас: **код проходит изолированные проверки, коммерческий релиз не принят**. Установка на Ubuntu 24.04, живой Telegram/Mini App, спонсор, Stars/СБП и восстановление реального стенда остаются обязательными. GitLab не входит в процесс выпуска. Тег релиза и публичный деплой не выполнять до успешной CI/staging/VPS приёмки. Следующие коммиты — только исправления дефектов/тестов/инсталлятора, без новых продуктовых функций.
