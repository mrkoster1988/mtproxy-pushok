# MTProxy Pushok — критерии приёмки MVP (v0.050, интеграционный PR #23)

**Статус: коммерческая приёмка НЕ выполнена.** Рабочая ветка содержит проверяемую основу рекламного кабинета и ручной активации/снятия спонсора; интеграция не равна опубликованному релизу или запуску MTProxy.

Единый процесс исходного кода и проверок — [GitHub](https://github.com/mrkoster1988/mtproxy-pushok). Обязательное условие для решения о слиянии — успешный CI **на последнем SHA** PR #23 и закрытая стендовая [задача #25](https://github.com/mrkoster1988/mtproxy-pushok/issues/25). Предыдущие успешные проверки не распространяются на новые коммиты.

## Область MVP

Кабинет рекламодателя: канал с `@username`, настраиваемый базовый тариф «1 день — 300 ₽», модерация, статусы оплаты, календарь и назначение слота; панель оператора: регистрация MTProxy-тега, ручной выбор продвижения в `@MTProxyBot`, запись наблюдений и завершение с аудитом.

Telegram Stars и СБП — обязательное направление коммерческого MVP, но **реальные оплаты, реальный эквайринг, обработка возвратов и тестовая транзакция Telegram ещё не подтверждены**. Коммерческие Stars-счета запрещены до приёмки через `PUSHOK_STARS_PAYMENTS_ENABLED=0`. Детали — [PAYMENTS_STARS_SBP.md](PAYMENTS_STARS_SBP.md).

**Не подтверждено:** автоматическое переключение спонсоров, настоящие показы/охват из Telegram API, рабочий Bot API на VPS, промышленные платежи и публичное размещение.

## Контрольные барьеры перед слиянием и пилотом

| Контроль | Подтверждение |
|---|---|
| CI на текущем SHA | GitHub Actions: `test` (Python/PostgreSQL), `compose-smoke`, `cabinet-preview`, `rust-core`, всё `success`. |
| Автономные проверки | `python3 scripts/preflight.py`, `python3 scripts/verify_release.py --mode offline`. Они не доказывают работу MTProxy/Telegram. |
| Приватная установка | На **отдельном** тестовом Ubuntu 24.04 VPS: `bash setup.sh --plan`, затем явное решение о локальной установке. Никакого изменения рабочего VPS. |
| Изоляция | `bash scripts/staging_preflight.sh --cabinet-only` (без бота) или `--with-bot` (бот настроен), проверка внутренней DB, закрытых прав `.env`, выключенных платёжных счетов и отсутствия публичных портов. |
| Сохранность данных | PostgreSQL миграции, backup/restore, отсутствие секретов в логах, повторный запуск с сохранением `.env`. |
| Настоящий Telegram/MTProxy | Рукопожатие MTProxy и подключение, ручное `Set promotion`, появление спонсора на независимом неподписанном клиенте, снятие и возврат собственного канала. |
| Безопасное завершение | Свежая запись `not_visible` после активации, два обязательных подтверждения и соответствующий аудит; повторное закрытие — HTTP 409. |
| Платежи | Отдельная приёмка тестовых Stars и СБП/провайдера. Без неё коммерческий запуск запрещён. |

Результаты живой приёмки хранить приватно: SHA, UTC, ответ API, журнал восстановления и доказательства без чужих данных или секретов. Сама отметка оператора **не является доказательством Telegram API**.

## Актуальный контракт завершения кампании

После фактического ручного снятия платного спонсора оператор записывает наблюдение в `POST /api/v1/operator/campaigns/{id}/display-observations`, указав `result=not_visible`, `method=separate_unsubscribed_client`, время и примечание. Последнее наблюдение должно быть не старше 10 минут по `observed_at` и `recorded_at`, а время наблюдения — **после** зафиксированной активации.

Затем оператор вручную возвращает собственный канал Pushok и проверяет его в отдельном Telegram-клиенте. Только после этого можно вызвать `POST /api/v1/operator/campaigns/{id}/complete`:

```json
{"tag_removed_confirmed":true,"own_channel_restored_confirmed":true,"verification_method":"separate_unsubscribed_client"}
```

Пропущенное либо `false` подтверждение → HTTP **422**; отсутствие актуального отрицательного наблюдения или неактивная кампания → HTTP **409**; отсутствующая кампания → HTTP **404**.

Система отмечает это как **`source=operator_attestation`, `telegram_api_verified=false`**. API самостоятельно не меняет конфигурацию MTProxy и не управляет `@MTProxyBot`.
