# Pushok Source Core · v0.026

**Статус: подготовлена кодовая база для собственной сборки.** Ни один Rust-бинарник не собран в CI или на VPS. Запуск существующих MTProxy, Telegram-бота, оплаты и веб-кабинета не менялся.

## Почему не отдельная установка Telemt

Официальный MTProxy и Telemt — разные реализации MTProxy; Docker — только способ упаковки. Для Pushok мы оставляем **единый административный API и единый мастер**, а Rust-реализацию используем как исходный код для дальнейших изменений. На первом этапе важно получить повторяемый, проверяемый процесс сборки и стабильную исходную точку, а не копировать чужой живой процесс.

## Зафиксированный источник

- Исходный репозиторий: https://github.com/telemt/telemt
- Релиз: `3.5.17` (2026-11-08).
- Annotated tag `3.5.17` указывает на commit `66708d2866f3f3a4541c4fa67984d408e71a8af4`.
- `third_party/telemt/UPSTREAM.lock` — текстовая блокировка; `LICENSE` — полная исходная лицензия Telemt Public License 3.3; `NOTICE.md` — происхождение и статус модификаций.
- В v0.026 не копируем и не переписываем upstream `src/` непосредственно в главный репозиторий. Полная исходная рабочая копия загружается по конкретному SHA в `.build/pushok-core/` при `--fetch`; на этом этапе она неизменённая. Следующая итерация — собственные проверенные Rust-патчи с подробным манифестом изменений.

## Безопасная подготовка (без сервера)

Из корня репозитория от обычного пользователя:

```bash
bash setup.sh --core-plan
python3 scripts/prepare_pushok_core.py --tls-domain proxy.example.org
```

Команды выше ничего не изменяют. Для реального получения исходников в рабочем окружении разработчика:

```bash
bash scripts/fetch_pushok_core.sh --fetch
bash scripts/build_pushok_core.sh --build
```

Скрипты отказываются работать под root, сверяют точный Git SHA, версию `Cargo.toml`, неизменённую лицензию и наличие `Cargo.lock`. Сборка: `cargo build --release --locked`, Rust >=1.88. Исполняемый файл сохраняется как `telemt-upstream-<sha>`: это **не переименованный или модифицированный официальный релиз Pushok**, а неизменённый upstream с правами 0700, checksum и копией лицензии. Установка и автозапуск на VPS отсутствуют.

Для локального тестового конфига:

```bash
python3 scripts/prepare_pushok_core.py --tls-domain proxy.example.org --port 8443 --write
```

`--write` создаёт новый `.build/pushok-core/staging.toml` с правами 0600 и уникальным случайным 32-hex secret. Перезаписи существующего файла нет. В тестовом конфиге API выключен и слушатель только `127.0.0.1`. Публичное открытие, DNS, реклама и деплой в production не выполняются. Никогда не коммитить этот файл, не отправлять Telegram BOT_TOKEN или клиентский MTProxy secret в чат.

Рекламный TAG из @MTProxyBot задаётся отдельно через переменную окружения `PUSHOK_CORE_AD_TAG`; не надо ставить `ad_tag` из примера или секрет пользовательского подключения вместо TAG. Фактическое `Set promotion` не автоматизировано.

## Граница безопасности и лицензирования

Telemt использует собственную `TELEMT Public License`, не MIT/Apache. Сохраняем полный текст лицензии, copyright, обязательное уведомление о будущих модификациях. Не заявляем поддержку разработчиков Telemt и не присваиваем их обозначения. Перед распространением изменённого Rust-кода потребуется список диффов и юридическая проверка условий конкретной версии.

Нельзя считать ядро рабочим, пока не пройдены: реальная Rust-сборка; отдельный тестовый запуск с действительной TLS-конфигурацией; подключение Telegram-клиента; пробное отображение спонсорского канала и проверка возможности безопасного отката. Никаких переключений работающего прокси автоматически не делаем. Pushok VPN, Remnawave и RemnaShop не используются.
