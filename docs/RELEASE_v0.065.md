# v0.065: согласованная диагностика применения тега

Карточка узла раньше показывала готовность кампании и предлагала ждать агента,
даже когда над ней уже отображался успешный ответ. Теперь она сверяет текущий
план с подтверждением в БД и свежим отчётом для того же узла. После сверки
показывается «Тег применён; показ не проверен», а готовность по расписанию
остаётся отдельной строкой.

«Обновить диагностику» одновременно обновляет карточки узлов и статус под
автоприменением. Форма с ещё не сохранённым тегом не пересоздаётся.
При ошибке запроса прежний статус заменяется сообщением о недоступности.

Чужой, устаревший или ошибочный отчёт не подтверждает применение. Смена тега,
кампании или периода отменяет прежнее подтверждение. Применение конфигурации
не переводит кампанию в активный показ автоматически.

## Отдельная проверка Telegram

Добавлен ручной скрипт [check_telegram_promo.py](../scripts/check_telegram_promo.py):
запрос help.getPromoData выполняется через настроенный MTProxy с временной
пользовательской сессией. Инструкция, требования и ограничения описаны в
[TELEGRAM_PROMO_PROBE.md](TELEGRAM_PROMO_PROBE.md).

Ответ без спонсора относится только к проверенной сессии. Даже ответ с ожидаемым
каналом не заменяет проверку его отображения в приложении. После изменения
Set promotion учитывайте срок обновления, указанный самим @MTProxyBot.

## Обновление и проверки

После публикации в release/stable выпуск доступен через «Настройки → Система →
Установить обновление». Номер API и кабинета — 0.065. Новой миграции БД нет;
параметры прокси, таймер агента и регистрация канала остаются прежними.

Регрессии проверяют текущий и изменённый план, чужой и устаревший отчёт,
ошибку агента, отсутствие утечки полного тега и ревизии. Браузерный сценарий
использует отдельную PostgreSQL и имитированный локальный отчёт: проверяет
обе карточки, их обновление и сохранение черновика формы. Реальный показ
спонсорского канала в Telegram проверяется отдельно на работающем прокси.
