# v1.122 — Устойчивый вход Pushok Flow

## Исправления входа

Устранена воспроизведённая гонка: отложенный ответ `/me` прежнего входа мог показать аккаунт A на экране согласия, когда решение уже отправлялось с новой сессией B. Ответы Telegram, загрузка профиля и последующие этапы кабинета теперь проверяют поколение входа и конкретную сессию. При явном выходе локальное состояние очищается до удалённого отзыва; старый ответ выхода не может сбросить новый вход.

До привязки к аккаунту публичный код Flow сохраняется в `sessionStorage` вместе с исходным временем получения. Допускаются только эти два поля, строгий алфавит и длина; срок не больше пяти минут, будущие даты отвергаются. Перезагрузка и HTTP 401 прежней веб-сессии не теряют ещё действующий код. Тот же URL не продлевает срок; новый корректный код заменяет прежний. Неверная или повторная query-переменная очищает запрос. Вход после восстановления заново получает действительный профиль и проверяет запрос; явное согласие по-прежнему обязательно. Выход или смена уже привязанного аккаунта сбрасывает запрос.

Когда обычный веб-вход Telegram недоступен, страница предлагает открыть существующий `@mtproxy_pushok_bot` с тем же публичным кодом. Бот ведёт в прежний Mini App, где сервер проверяет подписанные Telegram `initData`. Ссылка строится локально только для закреплённого бота после проверки публичной конфигурации. Это не исправляет настройки домена Login Widget у Telegram и не заменяет их проверку.

После согласия экран сообщает, что разрешение сохранено. Если Flow уже отменил старый запрос, показывает другой код или исходный срок истёк, нужно начать новый вход. Разрешение старого запроса не связывается с другим устройством автоматически.

## Лимиты за общим прокси

Штатный Caddy → API не даёт надёжной индивидуальной идентичности по socket peer. Прежние ограничения по адресу могли объединять всех внешних пользователей. Индивидуальные лимиты теперь относятся к существующему устройству, сессии или проверенному аккаунту; общий предел остаётся первым gate.

| Операция | Индивидуальная идентичность | Лимит в минуту | Общий предел |
|---|---|---:|---:|
| Создать запрос | Нет | — | 120 |
| Опросить токен | Хеш `device_code` | 120 | 1200 |
| Просмотреть или подтвердить запрос | Хеш UUID проверенного пользователя кабинета | 60 | 600 |
| Прочитать профиль | Хеш Flow bearer | 120 | 1200 |
| Выйти | Хеш Flow bearer | 30 | 300 |

Некорректные credentials имеют общий ограниченный bucket операции. Глобальная попытка учитывается даже при последующем отказе индивидуального лимита. Для согласия глобальный gate выполняется до авторизации, индивидуальный — только после действительной проверки кабинета. Ротация неизвестных секретов не создаёт новые строки после глобального предела. `X-Forwarded-For` не используется. Чистка, блокировки, лимит записей и исходные сроки запросов/сессий сохранены; таблицы и сеть не изменены. В SQL 075 уточнён только комментарий.

## Проверки и выпуск

Регрессионные тесты используют искусственные аккаунты, подписанные тестовые данные Telegram, настоящие FastAPI/PostgreSQL и Chromium. Проверяются старый `/me`, конкурирующие callbacks Telegram, выход и повторный вход, перезагрузка, исходный TTL, HTTP 401, неверные данные хранилища, путь через бот/Mini App и явные approve/deny. Тесты лимитов проверяют общий proxy peer, независимые principals, подмену forwarded headers, глобальные пределы и ограниченное количество строк.

Публикация в `release/stable` допускается после полного CI точного коммита: API/PostgreSQL, кабинет, Rust и Compose. Рабочий сервер обновляется штатным updater. Наличие кода и успешные тесты не доказывают установку на VPS, настройку Login Widget или полный вход пользователя на телефоне.
