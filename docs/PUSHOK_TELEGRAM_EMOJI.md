# Pushok Custom Emoji — настройка кнопок бота

## Что уже подключено

Код добавляет `icon_custom_emoji_id` к шести действиям главного inline-меню, если функция включена и для действия указан ID. По умолчанию `PUSHOK_BUTTON_ICONS_ENABLED=0`: исходные кнопки сохраняются. Владелец сообщил о публикации [PushokIcons](https://t.me/addemoji/PushokIcons) с 12 значками ([Issue #49](https://github.com/mrkoster1988/mtproxy-pushok/issues/49)). Получение реальных ID и показ на кнопках пока не подтверждены.

| Действие | Кнопка | Предлагаемый визуальный смысл / исходный файл |
|---|---|---|
| `advertise` | Разместить рекламу | `megaphone.png` |
| `campaigns` | Мои кампании | `campaign.png` |
| `tariffs` | Тарифы | `price.png` |
| `channels` | Наш канал | `channel.png` |
| `help` | Помощь | `support.png` |
| `miniapp` | Открыть Mini App | `home.png` |

`miniapp` появляется только при корректной отдельной настройке Mini App. Ключ `buy` не поддерживается. Платёжные кнопки Stars не получают декоративный ID и продолжают использовать прежний callback.

## Получение ID опубликованного набора

1. Откройте успешный запуск **Pushok Icons - Telegram emoji pack** в GitHub Actions и скачайте артефакт `pushok-custom-emoji-png` с PNG и `manifest.json`. Распакуйте в `.build/pushok-emoji` внутри проекта. Манифест описывает исходные файлы и действия; его поле `telegram_pack_published: false` означает, что сборка сама не проверяет публикацию.
2. Получите актуальный каталог из Telegram командой ниже. Она вызывает только `getStickerSet(name=PushokIcons)`, не отправляет сообщений и не меняет настройки. Используйте токен основной среды Telegram. Если `TELEGRAM_BOT_TOKEN` отсутствует в окружении, в обычном терминале появится скрытый ввод. В чате, аргументах команд и коммитах токен не указывайте; `.env` утилита не читает и не исполняет.

```bash
PUSHOK_TELEGRAM_TEST_ENVIRONMENT=0 python3 scripts/fetch_pushok_emoji_catalog.py \
  --output .build/pushok-emoji/catalog.json
```

Каталог содержит `custom_emoji_id`, связанный обычный `emoji` (либо `null`, если Telegram его не передал) и `file_id` для каждого значка. Проверяются название, тип Custom Emoji, 12 уникальных ID и формат полей. Если набор изменился, сначала проверьте его в Telegram, затем явно задайте новое число через `--expected-count`. Порядок значков не используется для назначения действий. Каталог сохраняется атомарно с правами `600`; ошибка API не портит предыдущий файл, URL с токеном и ответ ошибки не печатаются. Размер ответа ограничен 1 МиБ, таймаут — 20 секунд; перенаправления и proxy из окружения отключены.

3. Сопоставьте изображение каждого значка с действием. Таблица выше — предложение по смыслу, а не доказанная привязка к опубликованным ID. `tariffs` может использовать календарь или карту после визуального выбора; `miniapp` можно оставить без Custom Emoji. Одинаковый обычный emoji у разных значков не подтверждает совпадение изображения. Сверьте изображение через Telegram/файл из `file_id`; утилита сохраняет метаданные, но не делает визуальное распознавание и не скачивает изображения.
4. Проверьте право бота на использование иконок. По [Bot API: InlineKeyboardButton](https://core.telegram.org/bots/api#inlinekeyboardbutton), оно есть у ботов с дополнительными именами, купленными на Fragment, либо для сообщений, напрямую отправленных ботом в личные чаты/группы/супергруппы, если владелец бота имеет Telegram Premium. Это условие платформы, а не гарантия готовности нашего бота. `getStickerSet` не проверяет это право; нужна тестовая доставка меню.
5. Создайте локальный `.build/pushok-emoji/ids.json`. Можно указать только часть действий: остальные кнопки сохранят прежний вид. Не назначайте значения по индексам массива.

Шаблон ниже **нерабочий**, пока плейсхолдеры не заменены реальными числовыми ID в кавычках:

```json
{
  "advertise": "<ID значка megaphone из вашего набора>",
  "miniapp": "<ID значка home из вашего набора>"
}
```

## Проверка и перенос в .env

Из корня установленного проекта:

```bash
python3 scripts/prepare_pushok_emoji_ids.py \
  --manifest .build/pushok-emoji/manifest.json \
  --ids .build/pushok-emoji/ids.json \
  --catalog .build/pushok-emoji/catalog.json \
  --format env \
  --output .build/pushok-emoji/icons.env
```

Утилита проверяет тип манифеста и действия MTProxy, повторяющиеся ключи, непустую карту, формат ID и принадлежность выбранных ID сохранённому каталогу PushokIcons. При ошибке ранее подготовленный файл остаётся прежним. Она не обращается к Telegram повторно, не доказывает визуальный смысл/доставку, не редактирует `.env` и не включает функцию. Каталог — локальный снимок, а не подписанное доказательство: перед приёмкой получите его заново. Без `--catalog` сохранён прежний режим проверки формата с явным предупреждением об отсутствии проверки принадлежности.

1. Откройте `.build/pushok-emoji/icons.env`: там одна строка `PUSHOK_BUTTON_EMOJI_JSON='...'`.
2. Замените ею существующую строку с этим ключом в `.env`, не создавая дублей. Не заменяйте весь `.env` файлом `icons.env`.
3. На отдельной тестовой установке с проверенным набором задайте `PUSHOK_BUTTON_ICONS_ENABLED=1`.
4. Для обновлённого кода пересоберите и пересоздайте только контейнер бота:

```bash
docker compose --profile bot up -d --no-deps --build --force-recreate bot
```

Простой `docker compose restart bot` не перечитывает переменные контейнера. При последующих изменениях только `.env` флаг `--build` можно опустить.

## Проверка и отключение

Откройте `/start` в отдельном тестовом чате: проверьте шесть действий, сохранность подписей, переход в канал и запуск Mini App. На тестовых данных проверьте «Мои кампании» и доступную кнопку Stars. Иконка не подтверждает оплату/активацию: состояние приходит с сервера.

При отказе Telegram установите `PUSHOK_BUTTON_ICONS_ENABLED=0` и пересоздайте контейнер той же командой. Если `sendMessage` получил явный отказ `400` по `icon_custom_emoji_id`, `BUTTON_ICON_INVALID` или Custom Emoji внутри ошибки разбора keyboard button, бот один раз отправляет то же меню без декоративных полей. Подписи, callback, URL и WebApp сохраняются. Общие ошибки прав, нераспознанные ошибки, таймауты, 429 и 5xx не вызывают такой повтор. Для `sendInvoice`, подтверждения/возврата Stars этот механизм не применяется. В журнал попадает только факт отказа, без ответа Telegram, ID и токена. Неизвестный формат отказа может потребовать ручного выключения флага. Нельзя считать локальную проверку ID проверкой доставки меню.

Некорректный JSON, чрезмерно глубокий/большой JSON, нулевые и нечисловые ID игнорируются ботом; неизвестные действия не меняют меню. CLI подготовки настроек строже: вместо игнорирования сообщает об ошибке.

## Статус приёмки

- Код и конфигурация Compose подключены; иконки выключены по умолчанию.
- Локальные тесты и CI проверяют карту действий, сохранность callback/URL/WebApp и платёжных кнопок, экспорт и формат настройки.
- Публикация набора заявлена владельцем. Реальные ID, визуальное соответствие, права конкретного бота, доставка меню и проверки Android/iOS/Desktop остаются отдельной ручной приёмкой. Issue #49 остаётся открытой до этих результатов; изменение `main` — после CI и приёмки, как указано в задаче.
- Нативное reply-меню этим PR не добавляется.

### Журнал живой приёмки (заполнить по факту)

Проводите проверки на отдельной тестовой установке; флаг иконок изначально `0`. Оплата и активация спонсора проверяются только на тестовых данных. Ни токен, ни полный `.env` в отчёт не включаются.

| Проверка | Статус сейчас | Что записать после проверки |
|---|---|---|
| `getStickerSet`, название/тип/12 ID | Не выполнена | Дата, число значков, результат команды |
| Визуальная карта шести действий | Не выполнена | Выбранные действия, подтверждённые изображения, пропуски |
| Право конкретного бота | Не подтверждено | Имя бота и результат доставки, без токена |
| Android | Не проверено | Версия клиента, скриншот меню, действия/переходы |
| iOS | Не проверено | Версия клиента, скриншот меню, действия/переходы |
| Desktop | Не проверено | Версия клиента, скриншот меню, действия/переходы |
| Ошибочный ID и отказ API | Только автоматические тесты | Фактический отказ и результат обычного меню |
| Выключение флага | Только автоматические тесты | Обычное меню после пересоздания бота |
| Кампании/модерация/Stars/СБП/спонсор | Живая регрессия не выполнена | Результат тестового сценария без реального списания |

Автоматические проверки каталога, сохранности действий и ограниченного повтора:

```bash
python3 -m unittest discover -s tests -p 'test_*emoji*.py' -v
python3 -m unittest discover -s tests -p test_pushok_button_icons.py -v
```

Все ID в этих тестах искусственные. Успех CI не подтверждает регистрацию этих ID и не заменяет клиентскую приёмку.
