# Pushok Custom Emoji — настройка кнопок бота

## Что уже подключено

Код добавляет `icon_custom_emoji_id` к шести действиям главного inline-меню, если функция включена и для действия указан ID. По умолчанию `PUSHOK_BUTTON_ICONS_ENABLED=0`: исходные кнопки сохраняются. Реальная публикация набора и работа в Telegram ещё не подтверждены.

| Действие | Кнопка | Файл из набора |
|---|---|---|
| `advertise` | Разместить рекламу | `megaphone.png` |
| `campaigns` | Мои кампании | `campaign.png` |
| `tariffs` | Тарифы | `price.png` |
| `channels` | Наш канал | `channel.png` |
| `help` | Помощь | `support.png` |
| `miniapp` | Открыть Mini App | `home.png` |

`miniapp` появляется только при корректной отдельной настройке Mini App. Ключ `buy` не поддерживается. Платёжные кнопки Stars не получают декоративный ID и продолжают использовать прежний callback.

## Подготовка набора

1. Откройте успешный запуск **Pushok Icons - Telegram emoji pack** в GitHub Actions и скачайте артефакт `pushok-custom-emoji-png` с PNG и `manifest.json`. Распакуйте в `.build/pushok-emoji` внутри проекта.
2. Зарегистрируйте собственный набор через @Stickers и получите фактические `custom_emoji_id`. SVG из кабинета не подходит вместо ID.
3. Проверьте право бота на использование иконок. По [Bot API: InlineKeyboardButton](https://core.telegram.org/bots/api#inlinekeyboardbutton), оно есть у ботов с дополнительными именами, купленными на Fragment, либо для сообщений, напрямую отправленных ботом в личные чаты/группы/супергруппы, если владелец бота имеет Telegram Premium. Это условие платформы, а не гарантия готовности нашего бота.
4. Создайте локальный `.build/pushok-emoji/ids.json`. Можно указать только часть действий: остальные кнопки сохранят прежний вид.

Шаблон ниже **нерабочий**, пока плейсхолдеры не заменены реальными числовыми ID в кавычках:

```json
{
  "advertise": "<ID значка megaphone из вашего набора>",
  "miniapp": "<ID значка home из вашего набора>"
}
```

## Проверка и перенос в .env

Из корня установленного проекта:

```bash
python3 scripts/prepare_pushok_emoji_ids.py \
  --manifest .build/pushok-emoji/manifest.json \
  --ids .build/pushok-emoji/ids.json \
  --format env \
  --output .build/pushok-emoji/icons.env
```

Утилита проверяет тип манифеста и действия MTProxy, повторяющиеся ключи, непустую карту и формат ID. При ошибке ранее подготовленный файл остаётся прежним. Она не обращается к Telegram, не проверяет существование ID, не редактирует `.env` и не включает функцию.

1. Откройте `.build/pushok-emoji/icons.env`: там одна строка `PUSHOK_BUTTON_EMOJI_JSON='...'`.
2. Замените ею существующую строку с этим ключом в `.env`, не создавая дублей. Не заменяйте весь `.env` файлом `icons.env`.
3. На отдельной тестовой установке с проверенным набором задайте `PUSHOK_BUTTON_ICONS_ENABLED=1`.
4. Для обновлённого кода пересоберите и пересоздайте только контейнер бота:

```bash
docker compose --profile bot up -d --no-deps --build --force-recreate bot
```

Простой `docker compose restart bot` не перечитывает переменные контейнера. При последующих изменениях только `.env` флаг `--build` можно опустить.

## Проверка и отключение

Откройте `/start` в отдельном тестовом чате: проверьте шесть действий, сохранность подписей, переход в канал и запуск Mini App. На тестовых данных проверьте «Мои кампании» и доступную кнопку Stars. Иконка не подтверждает оплату/активацию: состояние приходит с сервера.

При отказе Telegram установите `PUSHOK_BUTTON_ICONS_ENABLED=0` и пересоздайте контейнер той же командой. Ошибочный, хотя и числовой ID может привести к отклонению всего сообщения; автоматического повтора без иконок нет. Нельзя считать локальную проверку ID проверкой доставки меню.

Некорректный JSON, чрезмерно глубокий/большой JSON, нулевые и нечисловые ID игнорируются ботом; неизвестные действия не меняют меню. CLI подготовки настроек строже: вместо игнорирования сообщает об ошибке.

## Статус приёмки

- Код и конфигурация Compose подключены; иконки выключены по умолчанию.
- Локальные тесты и CI проверяют карту действий, сохранность callback/URL/WebApp и платёжных кнопок, экспорт и формат настройки.
- Публикация набора, реальные ID, права бота, доставка меню и проверка Android/iOS/Desktop остаются отдельной ручной приёмкой.
- Нативное reply-меню этим PR не добавляется.
