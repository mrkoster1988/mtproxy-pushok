# v1.86 — Первый резервный прокси

До этого дополнительный экземпляр создавался только при задержке рекламной очереди. Теперь владелец может заранее подготовить первый резерв без заявок и без запроса решения у модели.

## Включение

1. Обновите проект до v1.86 через «Версия и обновления».
2. Откройте «Профиль → Управление → ИИ и прокси → ИИ · Новые прокси».
3. Оставьте включённым автоматическое создание, отметьте **«Подготовить один резервный прокси»** и сохраните. Ранее выданное разрешение ИИ на создание прокси должно оставаться включённым.
4. Агент на следующем проходе (раз в 5 минут) проверит ресурсы, свободный порт и подключение владельца Telegram. Он запустит дополнительный экземпляр и проверит его регистрацию через @MTProxyBot. При паузе Telegram подготовка продолжится после указанного срока.
5. При работающем едином входе новый экземпляр с общим ключом попадёт в него автоматически. В «Единый вход и интересы» дождитесь свежего отчёта **«Доступно узлов: 2»**. Проверяйте подключение через кнопку на главной: старые прямые ссылки не становятся общими.

## Границы настройки

- Настройка действует, только пока нет ни одного задания создания дополнительного экземпляра. Уже созданный экземпляр считается первым резервом независимо от первоначальной причины. Новые экземпляры сверх него по-прежнему зависят от очереди и решения ИИ.
- При незавершённой подготовке продолжается то же задание с тем же портом. После пяти неудачных попыток требуется «Продолжить подготовку»; настройка не создаёт замену в обход ошибки. Изменение условий во время подготовки также требует её возобновления.
- Ограничения количества, одного нового экземпляра в сутки и ресурсов VPS сохраняются. Основной прокси не перезапускается. Порты единого и тематических входов зарезервированы, даже когда HAProxy ещё не запущен.
- До подтверждения регистрации новый узел остаётся на паузе. В журнале отдельно отмечается создание по настройке резерва; оно не приписывается решению модели.
- Это второй процесс на **том же VPS**, который участвует в распределении подключений. Он помогает при отказе отдельного прокси. При отказе всего VPS нужен другой сервер. Открытые соединения не переносятся; переключение происходит при новом соединении или переподключении.

## Проверка

Автоматические проверки используют отдельную PostgreSQL и подменённые ответы Telegram: пустая очередь, повторные и конкурирующие запросы, регистрация, лимиты, отключённые разрешения, занятые порты и сохранение настроек в браузере. Они не подтверждают создание второго экземпляра на рабочем VPS. После обновления требуется дождаться отчёта агента; затем проверить новое подключение через общий вход.
