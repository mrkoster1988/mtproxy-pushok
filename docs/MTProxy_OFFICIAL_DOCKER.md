# MTProxy Pushok — официальный Docker MTProxy (v0.023)

**Статус: только код тестовой установки.** Не запускался на пользовательском VPS, коммерческая публикация не подтверждена.

Документация: https://hub.docker.com/r/telegrammessenger/proxy/ и https://core.telegram.org/proxy.

**Осторожно:** Docker Hub показывает, что тег официального образа telegrammessenger/proxy:latest очень старый (более шести лет). До production нужно отдельно оценить поддержку, уязвимости, совместимость и закрепить проверенную версию/дайджест. В автоматическом тесте образ не скачивается.

## Выбор движка в русском мастере

Из авторизованной копии приватного репозитория запустите:

    sudo bash setup.sh

Мастер предложит выбрать компоненты, а для MTProxy — один из двух движков:

1. Официальный MTProxy Docker (изолированный Compose-проект).
2. Классический MTProxy из исходников Telegram (существующий systemd-установщик).

Telemt уже поддержан в реестре спонсорских тегов (v0.022) и может настраиваться вручную. Его автоматический установщик пока не готов: мы не выдаём его за реализованный.

Отдельный официальный мастер задаёт домен, TCP-порт, интерфейс (по умолчанию только localhost), TAG из @MTProxyBot (ввод скрыт, можно пропустить), число процессов и отдельное финальное подтверждение.

Безопасно просмотреть диалоги без изменений:

    bash setup.sh --plan
    bash install_official_docker.sh --plan

## Разделение и защита существующих сервисов

- Compose: compose.proxy-official.yaml; проект mtproxy-pushok-official отдельно от кабинета.
- Отдельный том proxy-data для данных официального MTProxy; в стандартный docker compose up кабинета этот файл не входит.
- Закрытые секреты в /etc/mtproxy-pushok/official-docker.env (root, 0600).
- Секрет подключения генерируется отдельно (16 случайных байт = 32 hex); не пересоздаётся при случайном запуске установщика.
- TAG (32 hex из @MTProxyBot) сохраняется отдельно и каждый раз передаётся контейнеру как переменная окружения, поскольку сам Docker-образ не гарантирует его сохранение.
- Порт по умолчанию 127.0.0.1:8443, а не публичный 443: работа RemnaShop и сайтов не изменяется.
- Порт статистики 2398 доступен только внутри контейнера и не публикуется в Интернет.
- Если уже есть старый контейнер, конфигурация, система классического MTProxy или занят порт, установщик отказывается заменять существующие данные.

Docker-администратор может видеть SECRET в переменных контейнера; официальный образ может также выводить его в журнале. **Не отправляйте в чат или issue docker logs, docker inspect, полный docker compose config, содержимое env-файлов и ссылки подключения.**

## Спонсорский канал

1. На отдельном тестовом VPS проверьте подключение к MTProxy с реального Telegram-клиента.
2. Зарегистрируйте IP:порт и пользовательский SECRET в @MTProxyBot.
3. Если TAG ещё не было, вручную добавьте TAG=... в root-only env-файл после резервной копии. Изменение требует отдельного согласованного пересоздания именно этого контейнера с временной остановкой подключений.
4. Через @MTProxyBot → /myproxies → Set promotion вручную выберите публичный канал.
5. Убедитесь в фактическом показе с Telegram-аккаунта, который не подписан на этот канал.

В кабинете тип движка official_docker возвращает только образец TAG=... для администратора. Оператор в ответе sponsor-readiness видит лишь последние 4 символа тега; включения рекламы через API нет. Классический бинарный MTProxy использует -P TAG, Telemt использует ad_tag в секции general; эти конфигурации не взаимозаменяемы.

## Проверки разработки

    bash -n install_official_docker.sh
    bash install_official_docker.sh --plan
    python3 -m unittest tests.test_official_docker_install tests.test_sponsor_planner tests.test_sponsor_api -v

GitHub Actions проверяет синтаксис, диалоги, валидацию Compose без скачивания образа и миграцию PostgreSQL. Настоящие подключения клиентов, рекламный TAG и обновления официального Docker-образа на VPS не проверялись.
