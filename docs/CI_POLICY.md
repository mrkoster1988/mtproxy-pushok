# MTProxy Pushok — политика разработки и CI/CD (GitHub only)

**Актуальное решение владельца: 11 ноября 2026 года.** Для MTProxy Pushok единственным источником кода, задач, Pull Request, CI/CD, changelog и релизов является GitHub: `mrkoster1988/mtproxy-pushok`. Внешние зеркала, альтернативные CI-пайплайны и их синхронизация исключены.

## Обязательная проверка каждого кандидата

1. Ветка разработки и PR в GitHub; `main` не меняется ради подготовки или незавершённого эксперимента.
2. `.github/workflows/check.yml` выполняет `test` (в том числе временная PostgreSQL и pytest-native сценарии платежей), `compose-smoke`, `rust-core`, `cabinet-preview`. Проверяем **последний SHA**, а не исторические результаты.
3. `scripts/preflight.py` проверяет согласованность версии, миграций, маршрутов и наличие полного CI. Проверка статическая, не доказывает работу службы.
4. Любой красный/неполный результат CI блокирует объединение; нельзя скрывать или отключать тесты ради зелёного статуса.
5. Для PR #23 дополнительно требуется независимая стендовая приёмка по `docs/SPONSOR_ACTIVATION_STAGING.md`: MTProxy handshake, реальный Telegram-клиент, ручное Set promotion, положительное наблюдение неподписанным клиентом, снятие спонсора и rollback.
6. Без подтверждения стенда PR остаётся Draft. Зелёный CI не означает ни проверку рекламных показов, ни готовность платежей Stars/СБП.
7. Никакого публичного деплоя или изменения рабочего VPS без отдельного согласования. Не коммитить ключи, теги прокси, чеки или личные данные.

## Локальные проверки (без запуска служб)

```bash
python3 scripts/preflight.py
python3 -m unittest discover -s tests -p 'test_preflight.py' -v
```

Полный тестовый прогон может создавать и удалять временные базы; **не** указывать производственную PostgreSQL. Использовать только выделенную тестовую базу и условия `PUSHOK_TEST_DB_ALLOWED=1` для CI.
