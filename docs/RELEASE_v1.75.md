# v1.75 — Диагностика во время работы автоматики

В v1.73 диагностика брала shared `host-lock`, а агент спонсоров и агент автосоздания удерживали этот же замок эксклюзивно. Обычный проход автоматики мог оставлять диагностику в состоянии «Агент занят обслуживанием», хотя обновление уже закончилось.

Теперь агенты берут shared `host-lock` и отдельный exclusive `proxy-operation-lock` в одном порядке. Диагностика читает настройки одновременно с обычной работой агентов. Обновлятор по-прежнему берёт exclusive `host-lock`: чтение настроек и операции агентов во время замены кода и контейнеров не выполняются.

Изменения прокси остаются последовательными. Агент автосоздания держит одну блокировку операции от восстановления прерванного запуска до чтения настроек и получения задания, без промежутка для другого агента. Занятая операция ожидается не более 30 секунд; между попытками освобождаются оба замка. При истечении ожидания задания не берутся и попытки не расходуются. Исключение внутри уже начатой операции не вызывает её повторного исполнения. Снятие истёкшего тега до ожидания обновления сохраняется.

Проверки используют настоящие файловые блокировки: совместимость чтения и работы агента, исключение параллельных изменений, запрет работы при обновлении, освобождение замков при ожидании и ошибках. Сценарии проверяются также через входные функции обоих агентов; команды запуска служб, Docker и Telegram подменены.

Миграций нет. Требуется штатное обновление проекта, включающее хостовые скрипты. Уже выполняющийся проход старой версии завершится со старой блокировкой; следующий проход использует новую. Проверка готовности не создаёт прокси, не подтверждает регистрацию в Telegram и не заменяет проверку фактического показа.
