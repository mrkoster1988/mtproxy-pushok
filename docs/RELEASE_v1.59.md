# v1.59 — Тематика каналов

В форме создания кампании появилось необязательное поле «Тематика канала»: 25 направлений по отраслям и интересам. Можно выбрать другую тему или «Не указывать». Выбор сохраняется для конкретной кампании, показывается в её карточке и модерации; прежние заявки остаются без темы. Цена, оплата, модерация и расписание от темы не зависят.

После проверки публичности запускается отдельный анализ. Название и описание поступают из Telegram Bot API getChat; дополнительно читаются до 8 последних доступных текстовых публикаций из публичного веб-превью `https://t.me/s/<username>`. Изображения и видео не анализируются. Превью может быть отключено или иметь другой формат: тогда используются только название и описание, что явно указано возле подсказки. Закрытые каналы не читаются, аккаунт владельца и его личные сообщения не используются.

Без дополнительных настроек работают консервативные правила по тематическим словам. Это не ИИ. Если сигналов мало или направления равнозначны, тема не подставляется. Ручной выбор, включая отказ от темы, не перезаписывается; смена канала сбрасывает прежнюю тему и отбрасывает поздние ответы. Анализ не блокирует создание кампании. Кнопка «Определить автоматически» повторно запрашивает подсказку, которая может быть закэширована на 10 минут.

## Необязательный ИИ

Поддержан OpenAI Chat Completions API со строгой JSON-схемой и проверкой категории по справочнику. ИИ отключён по умолчанию и включается администратором на сервере в `.env`:

```dotenv
CHANNEL_TOPIC_AI_ENABLED=1
CHANNEL_TOPIC_AI_API_KEY=<ключ проекта OpenAI>
CHANNEL_TOPIC_AI_MODEL=gpt-4.1-mini
```

После изменения переменных пересоздайте сервис API обычным способом развёртывания проекта. В стандартной Compose-установке из каталога проекта: `docker compose up -d --no-deps api`. Ключ не вводится в Mini App и не возвращается клиенту. Без ключа или при отказе провайдера используются правила. Только результат настоящего ИИ помечается «ИИ предложил».

При включении ИИ провайдеру передаются название, описание и ограниченные тексты открытых публикаций выбранного канала; телефон, дата рождения, платежи, профиль рекламодателя и сессия Telegram не передаются. Тексты не сохраняются в БД Pushok; запрос использует `store:false`. Правила хранения провайдера определяются вашим договором с ним. Инструкции внутри публикаций считаются недоверенными данными, модель не получает инструменты и секреты.

Тайм-аут публичного превью — 2 с, ИИ — 4 с; размер ответов ограничен. В одном процессе API не более двух анализов одновременно и 60 обращений к ИИ в час. Результаты кэшируются на 10 минут с разделением по каналу, среде Telegram и конфигурации ИИ. Эти пределы снижают число платных обращений, но не заменяют лимит бюджета в кабинете провайдера. Тестовая среда Telegram не читает production-превью.

## Обновление и проверка

Установить v1.59 через «Профиль → Версия и обновления» и переоткрыть Mini App. Миграция 052 добавляет nullable-поле со справочником допустимых значений; обновление старых отправок не нарушает их идемпотентность. ИИ требует отдельной настройки выше; базовые подсказки работают без неё.

Автоматические проверки покрывают сохранение и отсутствие темы, старые ключи повторной отправки, несовпадение параметров, список модератора, парсер публичных текстов, ограничения, ошибки и неподходящие ответы ИИ. В Chromium проверяются автоподстановка, ручной выбор и отказ, поздний ответ, смена канала, отказ анализа и ширина 320 px. В тестах внешние Telegram/OpenAI-запросы заменены фикстурами; это не подтверждение работы ключа или установки на VPS.

Источники интерфейсов: [Telegram getChat](https://core.telegram.org/bots/api#getchat), [публичное превью Telegram](https://t.me/s/telegram), [OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs).
