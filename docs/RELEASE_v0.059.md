# v0.059: применение подготовленных тегов

Это автоматизация конфигурации классического MTProxy на одном локальном VPS, не Telegram-аккаунта.

## Подготовка

1. В @MTProxyBot подготовьте тег, который связан с нужным каналом через Set promotion. Убедитесь, что Telegram принимает такую регистрацию для вашего узла. Нельзя использовать один тег для разных каналов и ожидать переключения канала.
2. В кабинете «Узлы → Автоприменение по расписанию» выберите узел и канал, вставьте тег и подтвердите соответствие. Секрет подключения MTProxy не подходит.
3. Узел должен быть активен в реестре; host/port должны совпадать с MT_PROXY_HOST/MT_PROXY_PORT в /etc/mtproxy-pushok/mtproxy.env. Для старых установок, где восстановление записало IPv4 вместо домена, агент также проверяет текущий IPv4 домена. При двух записях (домен и IP с одним портом) агент не выбирает узел автоматически; сначала нужно устранить неоднозначность. Новый repair сохраняет домен и не создаёт второй узел при наличии старой IP-записи. Агент поддерживает только установленную локально mtproxy-pushok.service, не удалённые VPS и не Docker-прокси.
4. Одобрите заявку и подтвердите оплату (или бесплатный админский тариф). Подбор расписания работает существующим worker. Для уже назначенной заявки на другом узле перенесите слот на подготовленный узел.

## Работа

Установщик агента вызывается repair_proxy.py при обновлении/восстановлении классического прокси. Таймер mtproxy-pushok-promotion.timer проверяет очередь через 20 секунд после окончания предыдущей проверки. Пока связей нет, настройки прокси не меняются.

Для ручной установки: `bash scripts/install_promotion_agent.sh`. Проверка: `systemctl status mtproxy-pushok-promotion.timer`, `journalctl -u mtproxy-pushok-promotion.service -n 20 --no-pager`.

Агент сохраняет исходный тег в приватном /etc/mtproxy-pushok/promotion-state.json, меняет только MT_PROXY_TAG, перезапускает фиксированную службу, сверяет её аргумент -P и проверяет TCP-порт. Перезапуск может кратко прервать клиентские соединения. Ошибка возвращает прежний env. Удаление связи, отмена или конец слота возвращают исходный тег. При сбое API истёкший тег восстанавливается по локальному сроку; выключенная машина/таймер не могут выполнить восстановление до следующего запуска.

Ручной активный показ без подтверждения агента не перехватывается. Изменённые адрес/порт или URL канала требуют повторного подтверждения связи. План повторно проверяется перед записью результата; устаревший план откатывается. При отсутствии актуального подтверждения интерфейс показывает это явно.

«Тег применён» означает только подтверждённую конфигурацию и TCP, не наблюдение рекламы. Telegram определяет показ и может обновлять данные с задержкой. «Активно» остаётся отдельным фактическим подтверждением оператора. Автоматизация Set promotion, авторизация пользовательского Telegram-аккаунта и автоматическое доказательство показа в этот выпуск не входят.

## Отключение

`systemctl stop mtproxy-pushok-promotion.timer`

Дождитесь завершения службы, затем `python3 scripts/promotion_agent.py --restore`. Не удаляйте state-файл до восстановления. Сохранённые связи можно отключить в кабинете; это также возвращает исходный тег при следующем проходе.

## Проверки

Unit-тесты: неизменность секрета, инъекции, идемпотентность, возврат после ошибки, истечение при сбое API, изменившийся план. PostgreSQL: права, подготовка связи, назначенный период, подтверждение, отмена, продолжение после ручной проверки показа. Реальный показ и применение на пользовательском VPS требуют отдельной проверки после установки.
