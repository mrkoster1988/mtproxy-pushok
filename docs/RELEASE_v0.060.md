# v0.060: устойчивое обновление и границы расписания

## Что изменено

Удаление старого Docker-образа API больше не блокирует копирование чеков:
используется установленный postgres:16-alpine, закреплённый по SHA. Помощник
работает без сети, под UID 10001 и читает том только для чтения. Если оба образа
отсутствуют, отказ происходит до остановки кабинета.

Экран обновления показывает этап сбоя. Назначать и переносить слот раньше
желаемой даты теперь нельзя. Уже сохранённые периоды автоматически не меняются.

## Обновление VPS

Установка запускается кнопкой в настройках или существующим таймером.
При состоянии failed таймер владельца пропускает попытки: после устранения
причины нужно нажать кнопку повторно. Старый обновлятор создаёт копию до
получения нового кода, поэтому при уже удалённом образе API сначала требуется
пересобрать и пересоздать API на текущей версии. Не удаляйте тома Docker.

После установки проверьте версию API, готовность базы и службы агента.

## Приёмка под ключ

- /start после очистки диалога должен выводить приветствие и актуальное меню.
- Создание заявки, модерация, бесплатный админский тариф и оплата проходят на
  одной странице. Для платных тарифов нужна отдельная приёмка реального платежа,
  повторного уведомления и возврата с настроенным магазином.
- Автоподбор выбирает свободный период не раньше желаемой даты; отмена освобождает его.
- Автоприменение требует заранее подготовленного тега для каждого канала.
  Set promotion в @MTProxyBot выполняет владелец; задержку Telegram учитывают
  отдельно. Сохранение привязки не доказывает показ.
- Агент должен применить тег в периоде и вернуть исходный после окончания
  или отмены. Реальный показ и снятие проверяются клиентом Telegram.
- Сбой копии запрещает миграцию; неудачное обновление нельзя считать установленным.

Это исправляющий выпуск. Без приёмки платежей, показа/снятия и восстановления
на VPS полная эксплуатационная готовность не подтверждается.
