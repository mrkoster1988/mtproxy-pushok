# Telegram Mini App

Первый этап: серверный вход по сырому `Telegram.WebApp.initData`.
`POST /api/v1/auth/telegram/miniapp`, JSON `{"init_data":"<сырая строка>"}`.
По умолчанию отключён: `PUSHOK_MINIAPP_ENABLED=0`.

Проверяются HMAC-SHA256 по официальному алгоритму Telegram, свежесть до 5 минут,
допустимое время в будущем, уникальность параметров, формат пользователя и replay.
Подписанные данные не журналируются. Сессия и роль работают как при Login Widget;
аккаунт определяется Telegram ID, прежние кампании сохраняются. `initDataUnsafe`
и параметры браузера не являются источником личности. Повтор того же initData
отклоняется даже при перестановке параметров; после выхода нужно заново открыть Mini App.

Клиент подключён по `/miniapp` (также `/miniapp/`), использует общие страницы и API.
Он получает безопасный флаг из `/api/v1/miniapp/config`, загружает официальный SDK
Telegram и передаёт только сырое initData в серверный endpoint. Login Widget
в этом режиме не подключается. При выключенном флаге виден экран ожидания;
обычный браузер без initData получает инструкцию открыть приложение из Telegram.

Сессия хранится в sessionStorage отдельно от веб-кабинета и привязана к hash
проверенного initData. При обновлении страницы повторная сессия не создаётся,
чужой старый кэш не используется. Выход отзывает серверную сессию и подавляет
автоматический повторный вход с теми же данными. При истечении сессии очищаются
данные кабинета и предлагается заново открыть приложение. initData и токен
не попадают в URL или сообщения об ошибках. Параметры запуска Telegram убираются
из адреса после чтения SDK.

Кнопка BackButton возвращает из карточки в список, из других разделов — на главную;
открытое мобильное меню закрывается первым. На главной нативная кнопка скрыта.
Светлая/тёмная тема реагирует на Telegram, отступы учитывают safe area.
Ссылки t.me открываются через openTelegramLink при наличии метода SDK.

Платёжный экран Mini App получает серверный счёт Stars и открывает его через
Telegram.WebApp.openInvoice. СБП, реквизиты и загрузка чеков в этом клиенте
не показываются. Это настройка интерфейса: внешний кабинет и его API продолжают
работать отдельно. Рублёвая цена заявки и цена XTR не конвертируются друг в друга;
цену Stars пользователь подтверждает в нативном окне Telegram перед оплатой.

## Подключение тестового стенда

1. Развернуть актуальный API/кабинет на HTTPS и проверить обычный Telegram-вход.
2. На отдельном стенде установить `PUSHOK_MINIAPP_ENABLED=1`, перезапустить API.
3. В BotFather для того же бота настроить Main Mini App / Menu Button с URL
   `https://<домен-кабинета>/miniapp`. Токен должен соответствовать этому боту.
   Настройки реального бота автоматически не изменяются.
4. Открыть приложение из бота; проверить каналы, создание заявки, календарь,
   отчёты, BackButton, темы, повторное открытие/обновление и выход на
   Android/iOS/Desktop. Обычный браузер с подставленным user_id не даёт вход.
5. Проверить Stars в Telegram Test Environment: pre_checkout_query и successful_payment
   должны обрабатываться запущенным ботом. Реальные платежи не включать до отдельной приёмки.

В браузерном CI подменяется только оболочка Telegram SDK; сервер принимает реальные
подписанные тестовые данные и работает с временной PostgreSQL. Проверяются общий
аккаунт, неверная подпись, отсутствие initData, выключенный флаг, отдельный кэш,
reload без replay, навигация, темы/отступы, запрет платёжных кнопок СБП, отзыв сессии
и выход. Это не заменяет живую приёмку Telegram и эквайринга.

Основа проверки: https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app
Текущий этап не подтверждает готовность живого Mini App, платежей или VPS.

## Кнопка в боте

В `.env` задайте `PUSHOK_MINIAPP_URL=https://<домен-кабинета>/miniapp` и
`PUSHOK_MINIAPP_ENABLED=1` на тестовом стенде. Compose передаёт оба значения боту.
После его перезапуска новое личное меню содержит web_app-кнопку «Открыть Mini App».
Неверный URL (HTTP, IP, логин/пароль, query/fragment, чужой путь) скрывает кнопку.
Это inline-кнопка в личном чате; BotFather Main Mini App / Menu Button — отдельная
настройка владельца. Работающий бот автоматически не перенастраивается и сообщения
из среды разработки не отправляются.

## Оплата Stars

Дополнительно требуется `PUSHOK_STARS_PAYMENTS_ENABLED=1`, тот же
`TELEGRAM_BOT_TOKEN` у API и бота, корректный `BOT_INTERNAL_SECRET` и работающий
polling-процесс бота (без конфликтующего webhook). Флаги по умолчанию выключены.
Миграция `020_stars_invoice_link.sql` применяется установщиком.

`GET /api/v1/campaigns/{id}/stars` возвращает приватное состояние своей заявки,
`POST /api/v1/campaigns/{id}/stars/checkout` создаёт/возвращает ссылку. Цена и плательщик
берутся сервером, не из JSON браузера. Используется общий payment_attempt с ботом:
снимок XTR, срок 10 минут, payer, precheckout и последующий receipt. Открытая СБП-попытка
не допускает второй способ оплаты. Ручной чек блокируется при ожидающем счёте Stars
до истечения срока без precheckout; предварительно одобренный счёт требует сверки. Предварительно одобренный счёт блокирует новый.

Ссылка createInvoiceLink сохраняется вместе с ID бота. Повтор после сетевой ошибки
создаёт ссылку для той же попытки и той же суммы, а не новую покупку. Параллельные
checkout сериализуются; разные ссылки одной попытки не обходят однократный precheckout.
При смене бота сохранённая Mini App-ссылка не переиспользуется. Старые бот-счета после
смены бота требуют отдельного разбора до возобновления приёма. Браузеру не передаются
токен бота, внутренний секрет или право подтвердить перевод.

Закрытие окна, в том числе callback paid, вызывает только чтение состояния API.
Единственное основание зачёта — successful_payment, полученный polling-ботом и
проверенный существующим внутренним обработчиком. Повтор receipt не зачисляет
платёж дважды. Отмена окна не аннулирует запись ожидающего счёта; её можно открыть
заново до истечения срока. Изменение цены при выпуске требует повторного просмотра
суммы в Mini App. SDK без openInvoice предлагает обновить Telegram до выпуска счёта.
Если receipt запаздывает, обновите статус; не оплачивайте повторно.

CI имитирует только createInvoiceLink и оболочку SDK. Настоящие Stars не покупаются
и не списываются; выпуск ссылки в боевом Bot API и живые мобильные клиенты остаются
отдельной приёмкой. Справочник: https://core.telegram.org/bots/api#createinvoicelink
