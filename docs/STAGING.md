# Приватный staging на Ubuntu 24.04

Назначение — проверить установку до эксплуатации. Эта инструкция не разворачивает сайт автоматически.

## 1. Изолированная проверка одной командой

В авторизованной копии репозитория с установленным Docker и Compose plugin:

~~~bash
bash scripts/smoke.sh
~~~

Сценарий создаёт уникальный Compose-проект pushok-smoke-<timestamp>-<pid>. PostgreSQL, API и том чеков отдельные; портов на хосте нет. Production .env не подключается. Проверяются повторная миграция, pg_dump/pg_restore, архивирование файлов, перезапуск без потери данных, HTTP и интеграционные тесты. В конце удаляются только ресурсы этого временного проекта, в том числе при ошибке.

## 2. Долгоживущий приватный стенд

Используйте отдельный VPS Ubuntu 24.04 или отдельную установку в каталоге staging, отдельный порт и уникальный COMPOSE_PROJECT_NAME в .env. Для минимального риска начните с отдельного VPS, где нет магазина.

~~~bash
sudo bash setup.sh
~~~

В диалоге выберите «Только спонсорский кабинет», затем назначение «Приватный staging». Мастер предложит имя проекта mtproxy-pushok-staging, локальный порт 8010 и не создаст публичный HTTPS. Укажите уникальное имя и свободный порт; Telegram можно настроить позже. Для каждой установки нужен отдельный каталог. Если у выбранного имени уже есть контейнеры или тома, мастер остановится без перезаписи.

Для просмотра с компьютера через SSH:

~~~bash
ssh -L 8010:127.0.0.1:8010 user@staging-server
~~~

Откройте http://127.0.0.1:8010/. База и чеки наружу не публикуются. Реальный Telegram Login Widget требует отдельно настроенного домена и HTTPS; SSH-стенд проверяет интерфейс и API, но не подтверждает такой вход.

## 3. Проверка конфигурации

После настройки `.env`, под его владельцем:

```bash
bash scripts/staging_preflight.sh
```

Сценарий проверяет конфигурацию без запуска сервисов; JSON-отчёт и ошибки описаны в [STAGING_PREFLIGHT.md](STAGING_PREFLIGHT.md). Если Telegram был отложен, сначала завершите его настройку. Администратор в БД и живые интеграции проверяются отдельно.

## 4. Приёмка

- Проверить готовность API и тариф «1 день — 300 ₽».
- Пройти сценарий тестовой кампании; реальный спонсорский тег проверять отдельно на тестовом узле.
- Повторный запуск мастера должен сохранить .env и данные.
- Сохранить pg_dump, архив тома чеков и конфигурацию с правами 0600 в закрытом месте. Содержимое .env — секреты.
- Восстановление реальной копии сначала проверять в новой пустой тестовой БД/томе. Не выполнять restore поверх рабочей базы.
- Не открывать стенд публично без решения владельца.

## Границы автоматической проверки

CI запускает контейнеры на GitHub runner, не на вашем VPS. Smoke-test использует только искусственные данные. Системные пакеты Ubuntu, настоящий Telegram Login и фактический спонсорский канал требуют отдельной проверки. Автоматический тест backup/restore подтверждает формат и данные тестовой копии, а не сохранность ещё не созданных production-бэкапов.
