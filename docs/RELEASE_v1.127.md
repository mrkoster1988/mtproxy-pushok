# MTProxy Pushok v1.127 — возврат в Flow после подтверждения

После подтверждения одноразового кода Pushok Flow в действующем кабинете Telegram Mini App окно согласия автоматически закрывается штатным методом `Telegram.WebApp.close()`, но **только** после проверенного серверного ответа `approved`. Данные авторизации, приватные токены и WireGuard-профили не передаются в браузер.

- Во внешнем браузере нельзя принудительно закрыть Telegram: пользователь возвращается в Flow обычным переключением приложений.
- При отказе, ошибке связи, истечении кода или неопределённом статусе окно не закрывается автоматически.
- У параметра `/assets/flow-account.js` обновлён cache-busting номер: старая версия JS не должна использоваться после установки v1.127.
- Основные права аккаунта, роли разработчика, билеты MTProxy → Shop, выдача peer и действующие настройки прокси не изменяются.

## Проверки перед переводом в `release/stable`

1. `API and PostgreSQL checks` на точном коммите main, включая безопасность веб-согласия, браузер и Docker Compose smoke.
2. Сверка `app.version == 1.127`, видимой версии в README, ссылок веб-ассетов и заметок.
3. После обновления VPS: открыть согласие по новому коду из Flow, подтвердить и проверить закрытие Mini App; затем удостовериться в авторизации и фактическом получении собственного WireGuard-профиля из Shop.
4. GitHub и ветка `release/stable` **не** обновляют рабочие контейнеры автоматически, если серверный updater не установлен и не подтверждён.
