# Доверенное подтверждение личности Flow → Shop (первый серверный контракт)

Pushok Flow уже авторизуется через существующий аккаунт MTProxy Pushok.
Shop хранит отдельные подписки. Для подтверждения единого пользователя
добавлен короткоживущий **однократный proof**, а не передача MTProxy-сессии Shop.

## Запрос

`POST /api/v1/flow/shop-ticket` с `Authorization: Bearer pfa_...` и
`{"consent":true}` — вызывается **только по подтверждённому выбору пользователя
в приложении**. Сеанс Flow должен оставаться действующим, пользователь не должен
быть заблокирован. Пароль/сессия кабинета не передаются.

Ответ: `{"ticket":"psb1.<payload>.<hmac>","expires_in":60}`.
Подпись: HMAC-SHA256 от `b"pushok-flow-shop-v1\\0" + payload_bytes`.
Заголовок payload — JSON с версией, issuer `mtproxy`, audience
`pushok-shop`, UUID существующего пользователя, подтверждённым Telegram ID,
временем выпуска, сроком 60 с и случайным `jti`. Все части передаются только
в HTTPS POST body. Пример не содержит настоящих секретов.

## Настройка

Оба сервера должны отдельно получить одинаковый **новый случайный** секрет
`FLOW_SHOP_BRIDGE_SECRET` в виде 64 строчных hex-символов. Его нельзя
подменять `SESSION_SIGNING_KEY` или WGDashboard API token.
При отсутствии секрета endpoint отвечает 503, не меняя пользовательские данные.
В коде и GitHub Actions секрет не хранится.

Shop должен проверять подпись, ttl, audience, одноразовый jti, соответствие
Telegram ID собственной базе и владение выдаваемым устройством. Временный
proof не является постоянной авторизацией, платёжным разрешением либо
командой на создание нового peer без отдельной политики Shop.

До завершения сверки Shop и Android этот контракт не используется приложением.
