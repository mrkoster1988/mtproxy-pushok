# Единый вход и интересы

Владелец включает функцию в **Профиль → Управление → ИИ и прокси → Единый вход и интересы**. По умолчанию она выключена. Поддерживаются основной native MTProxy и до трёх автоматически созданных native экземпляров на том же IPv4 VPS.

После установки обновления один раз выполните на VPS:

```bash
sudo bash /opt/mtproxy-pushok/scripts/install_proxy_gateway.sh --install-dependency
```

Команда устанавливает системный HAProxy и отдельные службы Pushok. Основной прокси не перезапускается. Фоновый агент сам пакеты не устанавливает. Обычное обновление проекта обновляет службы и таймер, но установка HAProxy нужна только один раз.

1. Включите единый адрес. По умолчанию используется TCP **10443**, старый основной **8443** сохраняется.
2. При необходимости включите подбор по интересам. Он использует ещё 25 постоянных портов: по умолчанию **10444–10468**. Порядок тем закреплён в коде.
3. Разрешите эти порты в firewall провайдера. При активном UFW агент добавляет только необходимые разрешающие правила, без отключения защиты. При выключении функции правила UFW остаются, listeners закрываются.
4. Дождитесь статуса «Единый вход работает» и подключитесь кнопкой с главной. Ранее сохранённая прямая ссылка сама не превратится в ссылку общего входа.

## Что происходит автоматически

- Агент каждые 20 секунд читает разрешения владельца и актуальные узлы из базы под общей блокировкой обслуживания.
- В пул входят только активные native процессы этого VPS с доступным TCP-портом и общим ключом. Настройки проходят проверку HAProxy до замены; при ошибке применения восстанавливается предыдущий конфиг.
- Общий ключ равен ключу основного прокси. Новые дополнительные экземпляры принимают его вторым `-S`, сохраняя собственный ключ и прямую ссылку. Старые экземпляры без общего ключа исключаются до планового перезапуска; агент не обрывает их соединения ради миграции.
- HAProxy проверяет TCP-доступность каждые 3 секунды и выбирает узел для нового соединения. Хеш адреса клиента уменьшает ненужную смену узла; пользователи за одним NAT могут попадать на один узел. Балансировка не знает Telegram ID.
- При отказе узла переподключение может попасть на другой. Уже установленный поток не переносится без разрыва. При мягкой перезагрузке конфигурации старые потоки обслуживаются до 30 минут.
- При ошибке агента новая общая ссылка перестаёт выдаваться; кабинет возвращается к прямым ссылкам. Уже запущенный gateway может продолжать работать по последнему валидному конфигу с TCP health checks. Когда нет подходящих узлов или функция явно выключена, gateway останавливается.

## Добровольные интересы

В **Профиль → Мои интересы** человек выбирает одну тему или оставляет «Не указывать». Сохраняются тема, версия согласия и время выбора. Удаление темы удаляет запись; другой пользователь не может читать или менять её через API. Переписка, контакты, подписки и история просмотра Telegram не собираются; ИИ не составляет скрытый профиль человека.

Тематический порт направляет новые подключения преимущественно на узлы с подтверждённым актуальным планом кампании соответствующей темы. Учитываются свежий ответ агента, ревизия плана, действующая привязка и период. Если совпадений или доступных подходящих узлов нет, используются остальные узлы. Тема кампании может быть определена существующим классификатором канала или задана вручную.

После смены темы нужно открыть новую ссылку подключения. Приложение не может незаметно менять настройки прокси в Telegram. Кнопка на главной учитывает сохранённый интерес; обычная кнопка бота выдаёт общий вход без персонального подбора.

Это предпочтение маршрута, не гарантия фактического показа рекламы: отображение спонсора зависит от Telegram и проверяется отдельно. Несколько экземпляров на одном VPS не защищают от отказа самого VPS и не увеличивают аудиторию сами по себе.

## Диагностика

```bash
sudo systemctl status mtproxy-pushok-gateway-agent.timer mtproxy-pushok-gateway.service
sudo journalctl -u mtproxy-pushok-gateway-agent.service -n 30 --no-pager
sudo /usr/sbin/haproxy -c -f /var/lib/mtproxy-pushok-gateway/haproxy.cfg
```

Статус «Нет доступных узлов с общим ключом» требует проверки процессов и ключей, а не повторного входа в Telegram. Ошибка порта требует свободного диапазона. Активные порты нельзя незаметно изменить: сначала отключите функцию, затем измените настройки и выдайте новые ссылки.

Проверки проекта используют настоящий HAProxy на loopback, изолированный PostgreSQL и Chromium. Они подтверждают маршрутизацию, резервирование, изоляцию интересов и интерфейс. Установку systemd/firewall на рабочем VPS и фактический показ спонсора нужно проверить после развёртывания.
