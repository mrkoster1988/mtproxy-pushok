# MTProxy Pushok — приёмка ручной активации спонсора

**Область:** PR #19, код на ветке `feat/v0.032-manual-sponsor-activation`. Это проверочный план для отдельного тестового узла. **Никакого доступа к боевому VPS, реальным рекламодателям и платёжным ключам.**

## 1. Автоматические проверки (обязательные)
- [ ] CI `test` успешен: Python unittest, PostgreSQL и отдельный pytest.
- [ ] CI `rust-core` успешен (это проверка сборки и изолированного теста, **не** успешное подключение Telegram).
- [ ] CI `cabinet-preview` успешен.
- [ ] CI `compose-smoke` успешен.
- [ ] Проверить повторный запуск после каждого коммита и актуальный SHA PR, не ориентироваться на старый зелёный CI.

## 2. Ручной тест на отдельном стенде
- [ ] Создать отдельный тестовый MTProxy-узел и резервную копию текущей конфигурации; не использовать боевой трафик.
- [ ] Убедиться, что администратор зарегистрировал tag; оператор видит ожидаемый узел, канал и период.
- [ ] Убедиться, что без модерации `approved`, оплаты `verified`, зарегистрированного tag, подтверждённого Telegram channel ID либо актуального окна размещения API отклоняет активацию (`409`).
- [ ] Снять положительное наблюдение с **другого, не подписанного на канал** Telegram-клиента. Это отчёт оператора, а не Telegram API-метрика.
- [ ] Убедиться, что старое (более 10 минут) или последнее отрицательное наблюдение не разблокирует активацию. Свежими должны быть **оба** времени: фактическое `observed_at` и `recorded_at`; поздняя запись старого наблюдения не должна помогать.
- [ ] Отправить неполный чек-лист, ложный флаг либо пояснение короче 20 символов — API должен вернуть `422` без SQL-изменений.
- [ ] Отметить три пункта чек-листа и отправить корректное пояснение (20–500 символов). При выполнении всех условий ожидать статус `active` и запись в `audit_events` с `source=operator_attestation`.
- [ ] Повторная активация должна отклоняться; не создавать второй аудит успешного запуска.
- [ ] В журнале не должны появляться `ad_tag`, токены, секреты или утверждение `telegram_api_verified=true`.

## 3. Закрытие теста и откат
- [ ] Вручную снять коммерческого спонсора через Set promotion и проверить его отсутствие у отдельного неподписанного клиента.
- [ ] Вручную вернуть собственный канал Pushok через Set promotion и проверить его видимость у отдельного неподписанного клиента.
- [ ] Завершить через API, только передав **оба** подтверждения: `tag_removed_confirmed=true`, `own_channel_restored_confirmed=true`. Пропущенный или ложный флаг обязан давать HTTP 422. Эти флаги — *заявление оператора*, не телеметрия Telegram.
- [ ] При любом неожиданном результате не маркировать кампанию как фактически подтверждённую; сохранить логи без секретов и вернуть конфигурацию тестового узла из резервной копии.
- [ ] Зафиксировать SHA, ссылку на успешный CI, наблюдение (в приватном журнале), итог проверки отката и решение о merge.

**Граница функциональности:** PR не управляет @MTProxyBot, не принимает живые платежи, не меняет конфигурацию прокси автоматически и не подтверждает показы через Telegram API. Без стендовой проверки PR остаётся Draft.
