# Аналитика кампаний

## Что измеряется

- **Охват MTProxy:** недоступен. Сервер не получает подтверждения того, что конкретный человек увидел спонсорский канал. Подключения к прокси и успешная установка тега не являются показами.
- **Охват ссылки:** уникальные браузеры, загрузившие страницу отдельной ссылки с JavaScript либо нажавшие «Открыть канал». Первый просмотр в браузере сохраняется один раз на кампанию; предварительная загрузка HTML без скрипта не записывает событие.
- **Переходы:** уникальные браузеры, нажавшие кнопку перехода к приглашению канала. HTTP GET сам по себе переход не учитывает.
- **Подписки:** уникальные участники, впервые зафиксированные по созданному ботом приглашению; источник — Telegram `chat_member` с `invite_link`. Повторы обновления и повторное вступление того же аккаунта не увеличивают счётчик.
- **Конверсия:** подписки / переходы × 100%. Это отношение агрегатов, без сопоставления браузера с личностью Telegram. При нуле переходов или если подписок больше переходов процент не показывается. Приглашение могут переслать напрямую.

Cookie живёт 30 дней. Удаление cookie, смена устройства, запрет JavaScript и автоматизированные браузеры влияют на оценку охвата ссылки. Нельзя называть её охватом спонсорского блока. Ранее произошедшие события не восстанавливаются.

## Подключение

1. Добавить бота кабинета администратором рекламируемого канала с правом приглашать пользователей (`can_invite_users`). Это действие выполняет владелец канала в Telegram.
2. Открыть кампанию и нажать «Подключить подсчёт». Приложение проверит канал и права бота и создаст отдельное дополнительное приглашение. Основная ссылка канала не заменяется.
3. Использовать полученную ссылку `https://домен/r/<случайный токен>` в публикациях и рекламе. Прямые открытия спонсорского канала MTProxy этой ссылкой не проходят и не учитываются.

Бот уже запрашивает `chat_member` в getUpdates и передаёт события в защищённый внутренний API. Повтор доставки безопасен. Подключение счётчиков не изменяет состояние кампании, теги прокси или оплату. Нужны настроенные `TELEGRAM_BOT_TOKEN`, `BOT_INTERNAL_SECRET`, `SESSION_SIGNING_KEY`, `PUSHOK_MINIAPP_URL=https://домен/miniapp`, запущенный polling-бот и доступный кабинет HTTPS. При изменении канала, бота или среды Telegram прежняя ссылка перестаёт открывать канал; исторические показатели сохраняются.

Обновление добавляет миграцию `049_campaign_analytics.sql`; установка через существующий обновлятор сначала создаёт резервную копию и применяет миграции. После архивации кампании публичная страница не работает. Доставленные позже вступления учитываются только с датой события до архивирования. Прямое приглашение Telegram остаётся дополнительной ссылкой; при необходимости администратор может отозвать его в Telegram.

## Хранение и доступ

Владелец видит только свои кампании; оператор и администратор — доступные им отчёты. Ссылки статистики не открывают доступ к цифрам без сессии. Публичная страница содержит название канала и кнопку, а не сведения рекламодателя. IP, User-Agent, имена и Telegram ID участников не сохраняются. Для идемпотентности подписок хранится HMAC идентификатора с отдельным случайным секретом кампании; для браузера — подписанная случайная cookie и хеш в пределах кампании. Смена ключа сессий не создаёт повторных подписок. Это псевдонимные технические записи, не список профилей.

Просмотры записываются отдельным POST после выполнения скрипта; переходы — POST формы с подписанным, привязанным к cookie действием со сроком 15 минут. Неподписанные POST отклоняются. Перенаправление идёт только на приглашение, выданное Bot API. Вступления принимает внутренний API с секретом бота и проверкой среды Telegram, канала, бота и даты события.

История — с момента подключения. Агрегаты охватывают всё время ссылки; таблица показывает последние 30 дней с событиями в часовом поясе Europe/Moscow. Экран обновляется каждые 30 секунд, пока открыт. Удаление браузерной cookie не удаляет сохранённую агрегированную историю.

## Проверка

Тесты используют отдельную PostgreSQL и Chromium. Проверяются права, отсутствие накрутки при повторе одного события, подпись cookie/действия, разделение сред, неверные приглашения и канал, архив, отказ Telegram и отсутствие персональных ID в отчёте. В браузере проверяется путь от создания ссылки до перехода и подтверждённой подписки. Внешний Telegram и реальные люди в тестах не задействованы. Первая проверка на VPS должна подтвердить приём настоящего chat_member после вступления тестового аккаунта по ссылке.

Документация: [ChatMemberUpdated](https://core.telegram.org/bots/api#chatmemberupdated), [createChatInviteLink](https://core.telegram.org/bots/api#createchatinvitelink), [getUpdates](https://core.telegram.org/bots/api#getupdates).
