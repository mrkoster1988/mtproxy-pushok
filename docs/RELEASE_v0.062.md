# v0.062: восстановление после сбоя смены спонсора

Исправлен сценарий, когда предыдущая кампания отменена и агент переключается
на новый тег. Если запуск с новым тегом не удавался, возвращался прежний env
с рекламным тегом старой кампании, а локальный срок уже соответствовал новой.
При последующей недоступности кабинета старый тег мог сохраняться дольше,
чем предполагалось.

Теперь агент возвращает исходный тег узла, сохранённый до начала автоматического
размещения. Это может быть собственный спонсорский тег владельца либо отсутствие
тега. Секрет подключения, адрес и порт не меняются.

Перед изменением конфигурации агент сохраняет признак незавершённой попытки.
Он снимается только после успешного применения. При ошибке агент сразу пытается
вернуть исходный тег. Если восстановление не удалось или процесс прерван,
следующий запуск повторит восстановление до запроса к API и до ожидания обновлятора.
Приватный state-файл удаляется только после успешного восстановления.
Такой же повтор предусмотрен после неудачного возврата при отмене кампании
или изменении плана во время применения: потеря связи с API его не откладывает.

Старые state-файлы без нового признака остаются совместимыми. Успешно применённый
тег при временной недоступности API сохраняется в пределах назначенного срока.
По истечении срока исходный тег возвращается независимо от доступности API.
Остановленный сервер или отключённый таймер не могут выполнить восстановление:
оно произойдёт после возобновления работы агента.

## Установка и проверка

После публикации выпуска в `release/stable` используйте Mini App:
«Настройки → Система → Установить обновление». Нужна ранее установленная служба
обновления. Дождитесь успешного завершения и версии API `0.062`.
Обновлятор создаёт резервную копию и перезапускает сервисы; кабинет может быть
временно недоступен. Подробности: [инструкция обновления](RELEASE_v0.061.md).

В «Спонсоры и узлы → Диагностика спонсорского показа» ошибки применения и возврата
показываются отдельно. Ошибка возврата требует проверки: не считайте прежний тег
снятым, пока восстановление не подтверждено. Не удаляйте state-файл вручную.

Регрессионные тесты используют временные файлы и имитацию systemd, процесса
MTProxy и сетевых ошибок. Они проверяют смену и возврат конфигурации, а не
фактический показ канала в Telegram. Применение на пользовательском VPS и
наблюдение показа остаются отдельной проверкой.
