# Подключение владельца тегов MTProxy

Мастер подключает аккаунт владельца, а режим `enable` разрешает агенту автоматически менять спонсорский канал через @MTProxyBot. Входить нужно в **тот аккаунт, где зарегистрированы ваши прокси и теги**. Токен @mtproxy_pushok_bot для этого не подходит.

## Подключение

1. В своём браузере откройте https://my.telegram.org/apps, войдите и создайте приложение в **API development tools**. Например: App title `Pushok MTProxy Owner`, Short name `pushokowner`, Platform `Other`. Если приложение уже создано, используйте его `api_id` и `api_hash`.
2. Обновите MTProxy Pushok штатным способом, затем в интерактивном терминале VPS выполните:

   ```bash
   sudo bash /opt/mtproxy-pushok/scripts/connect_telegram_owner.sh enable
   ```

3. Мастер создаст отдельное Python-окружение и попросит `api_id`, `api_hash`, номер аккаунта, код входа из Telegram и пароль 2FA, если он включён. Все эти значения вводятся скрыто в терминале. Не передавайте их в чат, аргументы команды или issue.
4. Успешное подключение возвращает `"state": "connected"`, Telegram ID и username аккаунта. В Telegram → Настройки → Устройства появится **Pushok MTProxy Owner**.

Если на Ubuntu нет `python3-venv`, установите его командой `sudo apt-get install python3-venv` и повторите запуск. Мастер поддерживает повторный запуск после прерванной установки. Вне интерактивного терминала вход не запускается.

## Проверка и отключение

Проверить текущий вход через Telegram:

```bash
sudo bash /opt/mtproxy-pushok/scripts/connect_telegram_owner.sh status
```

Проверить только библиотеку и наличие сохранённой сессии, без авторизации в Telegram:

```bash
sudo bash /opt/mtproxy-pushok/scripts/connect_telegram_owner.sh check
```

Отозвать именно эту сессию и удалить сохранённые данные:

```bash
sudo bash /opt/mtproxy-pushok/scripts/connect_telegram_owner.sh disconnect
```

Если Telegram недоступен или отзыв не подтверждён, файл остаётся для повторного отключения. Можно отозвать сессию **Pushok MTProxy Owner** в официальном клиенте Telegram, затем повторить `disconnect`. При `state: revoked` сначала выполните `disconnect`, затем `connect` для нового входа. Временная ошибка сети не считается отзывом авторизации.

## Автоматическая привязка (v1.47)

После `enable` агент берёт одобренную и оплаченную заявку (включая бесплатный одобренный тариф), которой не хватает готовой привязки. Прокси уже должен быть зарегистрирован в этом аккаунте через `/newproxy`; вводить тег вручную для каждой новой кампании не требуется. Пока поддерживается локальный MTProxy Classic, установленный на VPS кабинета. На каждом управляемом VPS требуется его хостовый агент.

1. Свободный узел резервируется в БД. Активные и ручные размещения не перехватываются; близкие подготовленные слоты и брони учитываются.
2. Агент снимает предыдущий рекламный тег с процесса прокси. Открывает `/myproxies` и выбирает единственную запись нужного адреса и порта. Читает именно поле Tag, не secret.
3. Проверяет, что тег не используется другим известным узлом. Удаляет старую связь этого тега из кабинета до внешней записи.
4. Нажимает полученную от бота кнопку `Set promotion`, отправляет публичную ссылку, заново открывает карточку и сверяет адрес, тег и поле спонсорского канала. Слова `Success` недостаточно.
5. При подтверждении канала резервирует полный период с учётом желаемой даты и занятости узла. Плановое время видно в «Автоприменении». Выдерживает минимум час для обновления Telegram, снова читает карточку и только после совпадения публикует готовую связь. Планировщик выбирает ближайший полный период на подходящем узле. Подготовка не списывает время тарифа.
Если во время повторной проверки та же карточка показывает `n/a`, агент возвращается к назначению. После нового подтверждения час отсчитывается заново. На свободном узле агент также перепроверяет сохранённую связь для ближайшей автоматической кампании или канала по умолчанию, с интервалом не менее 15 минут.

6. После кампаний восстанавливает настроенный канал по умолчанию тем же способом. Пока новая привязка не проверена, рекламный тег снят; прокси продолжает принимать соединения. Старый baseline автоматически не возвращается, поскольку тот же тег уже мог быть связан с другим каналом.

Аккаунт нужен только для диалога с @MTProxyBot. Автомат не читает другие чаты, не подписывается на каналы, не меняет администраторов и не отправляет сообщения рекламодателям. Callback-данные не выдумываются: нажимаются только кнопки из текущего ответа бота.

Повтор после сбоя сначала читает текущую привязку. Если изменение уже принято, повторная запись не нужна. Ограничение FloodWait выдерживается полностью; попытки не идут каждые 20 секунд. Неизвестный формат, дубли адреса, смена аккаунта или канала останавливают подтверждение и отображаются в кабинете. Очередь переживает рестарт и не освобождает незавершённую внешнюю операцию по истечении короткого таймаута.

Отключить новые действия, сохранив вход:

```bash
sudo bash /opt/mtproxy-pushok/scripts/connect_telegram_owner.sh disable
```

Уже подготовленные привязки продолжают работать. Незавершённая привязка остаётся заблокированной до повторного `enable` и проверки результата. Не управляйте одновременно тем же прокси вручную в @MTProxyBot. Сменив его там, перепроверьте готовые привязки в кабинете.

## Состояние в кабинете (v1.49)

«Узлы и спонсоры → Автоприменение» показывает отдельную карточку подключения. Данные обновляются хостовым агентом; кнопка обновления читает отчёт и не запускает вход или изменение канала.

- **Нужен вход в Telegram** — сохранённой сессии нет; выполните `enable` на VPS.
- **Автопривязка выключена** — сессия есть, новые диалоги подготовки выключены.
- **Автопривязка включена** — агент недавно отчитался, вход проверен менее 15 минут назад. Владение тегом и фактический показ проверяются отдельно.
- **Сессия сохранена** — новой проверки входа ещё не было или она выполнена давно. Агент проверит вход перед привязкой; команда `status` проверяет его без изменения каналов.
- **Вход в Telegram отозван** — выполните `disconnect`, затем `enable`. До повторного входа новые узлы не резервируются.
- **Нет свежего отчёта агента** — состояние старше двух минут; дождитесь окончания проверки или проверьте службу.

В карточке указано время последнего подтверждённого входа, а в очереди — канал, узел и время следующей попытки. После `enable`, `disable` или `status` дождитесь следующего цикла агента. Отключение останавливает новое задание перед началом диалога; уже выполняющийся диалог удерживает блокировку, поэтому сначала дождитесь его завершения.

## Хранение и ограничения

- Сессия и API-реквизиты сохраняются только в `/var/lib/mtproxy-pushok/telegram-owner/owner.json`: каталог 0700, файл 0600, владелец root. Это данные входа в аккаунт; файл не предназначен для передачи или публикации.
- Код входа и пароль 2FA не сохраняются. Авторизация не помещается в `.env`, базу кабинета, Git, контейнеры или штатную резервную копию кабинета. В API и Mini App её нет.
- Два процесса не работают с одной сессией одновременно. Ошибка входа или сохранения вызывает попытку отозвать новую сессию; если отзыв не подтверждён, мастер просит завершить её в Telegram.
- Внешняя библиотека `Telethon==1.45.0` установлена отдельно в `/opt/mtproxy-pushok-telegram-owner-venv`. API и бот кабинета не получают эту зависимость.
- Команды `connect` и `status` проверяют профиль и адрес @MTProxyBot. Только явно включённый режим `enable` разрешает диалог подготовки канала.

`connected` означает успешный вход; `automatic_binding_enabled` показывает включение режима. Владение конкретным тегом проверяется отдельно при чтении карточки прокси. Статусы очереди: проверка регистрации → привязка → ожидание обновления Telegram → привязка проверена. Сообщение бота и истечение часа не являются доказательством показа канала в клиенте: эта проверка остаётся отдельной.

Тесты используют синтетические ответы бота и настоящую тестовую PostgreSQL. Живой диалог с аккаунтом владельца здесь не выполнялся. Формат @MTProxyBot не является стабильным API: если распознавание не совпало, код не нажимает случайные кнопки и не отмечает привязку успешной. Для проверки после включения нужна одна одобренная заявка, запись прокси в аккаунте и её состояние в кабинете. До первой успешной проверки считайте интеграцию требующей проверки на VPS.

Источники: [получение api_id](https://core.telegram.org/api/obtaining_api_id), [вход Telethon](https://docs.telethon.dev/en/stable/basic/signing-in.html), [хранение сессий](https://docs.telethon.dev/en/stable/concepts/sessions.html).

Дополнительно: [регистрация MTProxy](https://core.telegram.org/proxy), [управление спонсором в документации telemt](https://github.com/telemt/telemt/blob/main/docs/FAQ.en.md), [кнопки Telethon](https://docs.telethon.dev/en/stable/modules/custom.html#telethon.tl.custom.message.Message.click).

## Проверка канала (v1.50)

Свежий зелёный статус аккаунта означает доступ к сессии владельца, но не успешную проверку канала. Смотрите карточку очереди ниже: там указана точная ссылка из заявки и причина остановки.

- «По ссылке находится не канал»: Telegram вернул группу или пользователя. Нужен именно публичный канал.
- «Telegram не нашёл этот канал»: проверьте @username и доступность канала.
- «Адрес канала не подтверждён»: имя не совпадает ни с основным, ни с активными дополнительными именами.
- «Неверная ссылка на канал»: используйте https://t.me/username или https://telegram.me/username; приглашения и ссылки на посты не подходят.
- «Привязка проверена — ожидаем обновления Telegram»: это часовая пауза после подтверждения, а не ошибка. Период рекламы ещё не запущен.

Активные дополнительные имена обрабатываются по полям `channel.usernames` / `username.active` Telegram API. Если бот показывает основное имя, агент сверяет числовой ID, а не название канала. См. https://core.telegram.org/constructor/channel и https://core.telegram.org/constructor/username.

После обновления повторный вход не нужен: существующая очередь проверяется в указанное время. Старая общая ошибка «Канал не прошёл проверку» уточнится при следующем обращении агента к Telegram. Само обновление не подтверждает успешную живую привязку.
