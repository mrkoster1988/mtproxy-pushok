# v1.69 — Восстановление автосоздания и паузы Telegram

Продолжение [автосоздания прокси v1.67](RELEASE_v1.67.md). Обновление не включает ИИ автоматически и не меняет выбранные лимиты. Доработка не добавляет новых миграций поверх v1.68.

## Пауза Telegram

Ограничение FloodWait сохраняется в приватном файле аккаунта на VPS. Перезапуск агента, смена задания, кнопка повтора и ручная проверка подключения не сокращают срок. Все операции регистрации и привязки этого аккаунта ждут окончания паузы. Привязка не снимает текущий тег ради заведомо заблокированного запроса. Отключить автоматику и отозвать сессию можно во время ожидания.

В разделе **Настройки → Система → ИИ · Новые прокси** отображается время следующей попытки. Пока действует ограничение, кнопка повтора недоступна, а API отклоняет преждевременный повтор. Обычная ожидающая задача продолжается по таймеру. После пяти неудачных попыток нужно дождаться паузы, обновить состояние и нажать «Продолжить подготовку». Ограничения дольше недели также сохраняются полностью.

Файл `/var/lib/mtproxy-pushok/telegram-owner/telegram-cooldown.json` содержит только ID подключённого аккаунта и срок ожидания; права 0600. Он не содержит сессию или телефон. Пауза привязана к аккаунту и не переносится на другой аккаунт.

## Восстановление после обрыва

Перед финальным подтверждением запуска агент записывает приватный `completion.json` в каталог экземпляра. Запись содержит ID задания и проверенный тег. После перезапуска он сначала сверяет каждый ранее созданный экземпляр с БД под общей блокировкой хоста:

- **БД уже приняла запуск:** служба сохраняется, повторное подтверждение не дублирует событие аудита.
- **Экземпляр готов, подтверждение не принято:** агент проверяет службу и таймер и повторяет только подтверждение. Обращения к Telegram и `/newproxy` не повторяются.
- **Подготовка прервана или разрешение отозвано:** агент останавливает только незавершённую службу, её таймер и агент. Остановка проверяется; ссылка удаляется из пула. UUID, порт и секрет сохраняются для продолжения.
- **БД недоступна или экземпляр не удалось однозначно сопоставить:** службы не останавливаются по предположению. Следующая попытка снова сверяет результат.

Ручная активация узла или уже запущенная на нём кампания исключают его из очистки незавершённых экземпляров. Если БД однозначно отклонила тег из-за конфликта регистрации, новая служба останавливается, причина попадает в очередь повторов.

Сверка выполняется до проверки свободной памяти, подключения Telegram и флага автосоздания. Поэтому выключенный ИИ не мешает завершить очистку незавершённой подготовки. Принятые БД рабочие экземпляры при выключении не удаляются. Основной прокси этим механизмом не останавливается.

Если процесс оборвался на пятой попытке до создания файлов, задача после окончания её интервала ожидания получает статус «Подготовка была прервана». Она больше не висит в бесконечной очереди. Действующая пауза Telegram при очистке сохраняется.

## Обновление и проверка

Достаточно штатного обновления установленного кабинета и хостового агента. Переподключать Telegram и заново вводить ключ OpenAI не нужно. Состояние появится при следующем запуске `mtproxy-pushok-provisioner.timer`.

```bash
sudo systemctl status mtproxy-pushok-provisioner.timer
sudo journalctl -u mtproxy-pushok-provisioner.service -n 30 --no-pager
```

Автотесты проверяют очередь в настоящем PostgreSQL, потерю ответа, повторное подтверждение, остановку незавершённой службы, сохранение паузы на диске, отказ преждевременного повтора и восстановление кнопки после паузы. Chromium проверяет интерфейс на ширинах 320/390/768/1280 px.

Telegram и systemd в этих сценариях заменены контролируемыми ответами. Это не подтверждает живой запуск на VPS или фактический показ спонсора; они требуют проверки после серверного обновления.

Основание обработки ограничения: [FloodWaitError в документации Telethon](https://docs.telethon.dev/en/stable/concepts/errors.html#common-errors).
