# MTProxy Pushok — подключение и проверка спонсорского канала

**Статус:** регистрация тега и предварительная проверка в этом документе только сохраняют данные. С v0.059 отдельный блок «Узлы → Автоприменение по расписанию» и локальный агент могут применять подготовленные теги к классическому MTProxy на VPS. Порядок настройки, ограничения и возврат исходного тега описаны в [инструкции агента](RELEASE_v0.059.md). Выбор канала через Set promotion и проверка фактического показа остаются отдельными действиями.

Обычная кнопка «Сохранить регистрацию» не включает агента и не создаёт связь для автоприменения. Для него нужны активный узел, подтверждённая связь канала с тегом и одобренная оплаченная кампания в назначенном периоде. Плашка «Планирование · без запуска» относится к выбору движка и не показывает состояние агента.

## Главное техническое ограничение

Прокси-спонсорство управляется инфраструктурой **Telegram**, а не стандартным Bot API рекламного кабинета. Проксирующий сервис предоставляет рекламный `ad_tag`, выданный **@MTProxyBot**; выбор отображаемого публичного канала выполняется через **@MTProxyBot → /myproxies → Set promotion**. Документированного публичного API для автоматического изменения этого назначения здесь **не используем**. Даже правильный `ad_tag` не доказывает, что рекламируемый канал уже показан подписчикам.

Документы:
- Telegram MTProxy: https://core.telegram.org/proxy
- Telemt FAQ (рус): https://github.com/telemt/telemt/blob/main/docs/FAQ.ru.md
- Telemt config: https://github.com/telemt/telemt/blob/main/config.toml

## Подготовка через Telegram

1. Зарегистрировать собственный MTProxy в **@MTProxyBot**, получив тег для конкретного прокси: `/newproxy`, IP:port, секрет пользователя.
2. Вручную добавить тег в реестр прокси-узлов кабинета с ролью `admin`. Новый API: `PUT /api/v1/admin/proxy-nodes/{node_id}/sponsor-registration` с `{"engine":"telemt","ad_tag":"<32 hex>"}` либо `{"engine":"official_mtproxy","ad_tag":"<32 hex>"}`. Никаких действий на VPS вызов не делает.
3. Получить пример конфигурации `GET /api/v1/admin/proxy-nodes/{node_id}/sponsor-config-preview`. Он доступен **только админу**; тег в других ответах показывается только последними четырьмя символами.
4. На **отдельном тестовом сервере**, после резервной копии и явного подтверждения владельца, администратор может вручную настроить прокси. Для Telemt фрагмент:
   ```toml
   [general]
   use_middle_proxy = true
   ad_tag = "ВСТАВЬТЕ_РЕАЛЬНЫЙ_ТЕГ_ИЗ_MTProxyBot"
   ```
   Для официального MTProxy тег передаётся аргументом `-P` при запуске. Это **не** MTProxy secret из ссылки подключения, не Telegram BOT_TOKEN.
5. В **@MTProxyBot → /myproxies → Set promotion** вручную указать *публичный* канал рекламодателя. Показ может обновиться не сразу. Учитывайте срок, указанный самим MTProxyBot после сохранения; в подтверждённом сценарии бот предупредил об ожидании до одного часа.
6. В своём Telegram-аккаунте, **не подписанном** на продвигаемый канал, подключиться к MTProxy этой кампании и проверить отметку **«Спонсор прокси»** у канала в списке чатов. Второй аккаунт не требуется. Наличие канала в подписках или успешный ответ агента не заменяют эту проверку.

## Предварительная проверка заявки

Оператор выполняет **только чтение**:
`GET /api/v1/operator/campaigns/{campaign_id}/sponsor-readiness`.

Система проверяет:

- `moderation_status = approved`;
- `payment_status = verified` (не статус «ожидает оплаты» и не загруженный чек);
- `placement_status = scheduled` и не истёк срок размещения;
- выбранный узел активен;
- публичный канал прошёл проверку и имеет числовой Telegram channel ID;
- на узле есть зарегистрированный тег `ad_tag`.

Ответ содержит `checks`, `ready_for_manual_preparation`, сокращённый тег, сведения о узле и **порядок ручных действий**. Даже значение `true` не означает, что настройки прокси или Telegram были изменены: `changes_applied` всегда `false`.

### Что защищено

- Только `admin` может зарегистрировать или обновить тег узла и увидеть полный фрагмент конфигурации.
- `operator` / `admin` могут проверить готовность заявки, но **без полного тега**.
- Если на прокси есть `scheduled` или `active` кампания, менять зарегистрированный тег запрещено.
- Проверка не может сама активировать кампанию, провести оплату, изменить Telegram Set promotion или перезапустить сервис.
- Изменения в реестре журналируются без записи полного тега в журнал.
- Неверные и пустые теги, включая 32 нуля, отклоняются.
- Для существующей БД миграция `database/007_proxy_sponsor_registration.sql` повторяемая и не удаляет пользователей и кампании. Требуется резервное копирование **до** применения.

## Как сохранить наблюдение в кабинете

1. Откройте Mini App → меню ☰ → **Узлы** → **Очередь размещений**.
2. В нужной кампании нажмите **Управлять размещением**.
3. В блоке **Подтвердите фактический показ** опишите текущую проверку в Telegram.
   Прикрепите скриншот с отметкой «Спонсор прокси», если он есть.
4. Подтвердите подключение к нужному прокси, отсутствие подписки и видимый показ;
   нажмите **Подтвердить показ и активировать**.
5. Убедитесь, что появился статус **Размещение активно**. Если API отклонил
   активацию, прочитайте причину: запись наблюдения и активация — разные операции.

Наблюдение должно быть свежим и относиться к назначенному периоду. При позднем
заполнении формы проверьте текущий показ заново: старый скриншот не подтверждает
состояние на момент нового наблюдения. Второй аккаунт не нужен, однако аккаунт,
с которого выполняется проверка, не должен быть подписан на рекламируемый канал.

Имя метода API `separate_unsubscribed_client` сохранено для совместимости.
Это ручная проверка в Telegram отдельно от кабинета, без подписки на канал;
это не требование другого номера телефона и не автоматическая проверка Telegram.

## Завершение и исходный тег

При включённом автоприменении агент после окончания периода возвращает тег,
сохранённый перед первой управляемой кампанией. Он может быть пустым, вести на
канал владельца или совпадать с тегом завершившейся кампании. В последнем случае
возврат настроек не обязан убирать канал из списка спонсоров.

После окончания периода отдельно проверяются возврат конфигурации на VPS и
показ в Telegram. **Подтвердить завершение** сохраняет сообщение оператора
о снятии тега кампании и прекращении её показа; кнопка сама не управляет Telegram.
Если исходный и рекламный теги совпадают, не отмечайте отсутствие канала как
проверенное. Для испытания прекращения показа заранее согласуйте исходный тег,
отличающийся от рекламного, или отсутствие исходного спонсора.

Для проверки смены каналов нужны разные подготовленные теги с подтверждённой
привязкой в MTProxyBot. Повторное Set promotion у одного тега меняет его привязку
на стороне Telegram и не заменяет переключение разных тегов агентом.
