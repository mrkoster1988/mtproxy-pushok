# MTProxy Pushok — подключение реального спонсорского канала (v0.022)

**Статус:** код подготовки и проверок. **Не автоматическая публикация рекламы.** Ничего не меняет в Telemt, официальном MTProxy, Telegram или работающем VPS.

## Главное техническое ограничение

Прокси-спонсорство управляется инфраструктурой **Telegram**, а не стандартным Bot API рекламного кабинета. Проксирующий сервис предоставляет рекламный `ad_tag`, выданный **@MTProxyBot**; выбор отображаемого публичного канала выполняется через **@MTProxyBot → /myproxies → Set promotion**. Документированного публичного API для автоматического изменения этого назначения здесь **не используем**. Даже правильный `ad_tag` не доказывает, что рекламируемый канал уже показан подписчикам.

Документы:
- Telegram MTProxy: https://core.telegram.org/proxy
- Telemt FAQ (рус): https://github.com/telemt/telemt/blob/main/docs/FAQ.ru.md
- Telemt config: https://github.com/telemt/telemt/blob/main/config.toml

## Подготовка через Telegram

1. Зарегистрировать собственный MTProxy в **@MTProxyBot**, получив тег для конкретного прокси: `/newproxy`, IP:port, секрет пользователя.
2. Вручную добавить тег в реестр прокси-узлов кабинета с ролью `admin`. Новый API: `PUT /api/v1/admin/proxy-nodes/{node_id}/sponsor-registration` с `{"engine":"telemt","ad_tag":"<32 hex>"}` либо `{"engine":"official_mtproxy","ad_tag":"<32 hex>"}`. Никаких действий на VPS вызов не делает.
3. Получить пример конфигурации `GET /api/v1/admin/proxy-nodes/{node_id}/sponsor-config-preview`. Он доступен **только админу**; тег в других ответах показывается только последними четырьмя символами.
4. На **отдельном тестовом сервере**, после резервной копии и явного подтверждения владельца, администратор может вручную настроить прокси. Для Telemt фрагмент:
   ```toml
   [general]
   use_middle_proxy = true
   ad_tag = "ВСТАВЬТЕ_РЕАЛЬНЫЙ_ТЕГ_ИЗ_MTProxyBot"
   ```
   Для официального MTProxy тег передаётся аргументом `-P` при запуске. Это **не** MTProxy secret из ссылки подключения, не Telegram BOT_TOKEN.
5. В **@MTProxyBot → /myproxies → Set promotion** вручную указать *публичный* канал рекламодателя. Показ может обновиться не сразу (в Telemt FAQ упоминается ожидание около часа).
6. Отдельным Telegram-аккаунтом, **не подписанным** на продвигаемый канал, подключиться к тестовому MTProxy и проверить фактическое отображение. Без такого испытания мы не считаем размещение выполненным.

## Предварительная проверка заявки

Оператор выполняет **только чтение**:
`GET /api/v1/operator/campaigns/{campaign_id}/sponsor-readiness`.

Система проверяет:

- `moderation_status = approved`;
- `payment_status = verified` (не статус «ожидает оплаты» и не загруженный чек);
- `placement_status = scheduled` и не истёк срок размещения;
- выбранный узел активен;
- публичный канал прошёл проверку и имеет числовой Telegram channel ID;
- на узле есть зарегистрированный тег `ad_tag`.

Ответ содержит `checks`, `ready_for_manual_preparation`, сокращённый тег, сведения о узле и **порядок ручных действий**. Даже значение `true` не означает, что настройки прокси или Telegram были изменены: `changes_applied` всегда `false`.

### Что защищено

- Только `admin` может зарегистрировать или обновить тег узла и увидеть полный фрагмент конфигурации.
- `operator` / `admin` могут проверить готовность заявки, но **без полного тега**.
- Если на прокси есть `scheduled` или `active` кампания, менять зарегистрированный тег запрещено.
- Проверка не может сама активировать кампанию, провести оплату, изменить Telegram Set promotion или перезапустить сервис.
- Изменения в реестре журналируются без записи полного тега в журнал.
- Неверные и пустые теги, включая 32 нуля, отклоняются.
- Для существующей БД миграция `database/007_proxy_sponsor_registration.sql` повторяемая и не удаляет пользователей и кампании. Требуется резервное копирование **до** применения.

## Проверка кода (без реального VPS)

```bash
python -m unittest tests.test_sponsor_planner tests.test_sponsor_api -v
docker compose --profile bot config --quiet
```

Полный GitHub Actions дополнительно прогоняет тесты с отдельной PostgreSQL. Реальный тест Telegram sponsor / Telemt и подтверждение публикации остаются отдельным этапом.

**Важное ограничение коммерческого MVP:** тариф «1 день — 300 ₽» — стоимость **времени размещения**, а не гарантированных просмотров, переходов или подписчиков. Telegram-клиент может скрыть спонсорский канал.
