# Предпусковая проверка установки

Проверка читает `.env`, индекс Git и итоговую конфигурацию Compose. Контейнеры не запускаются, файлы и БД не изменяются, запросов в Telegram/эквайринг нет. Значения секретов, исходный вывод Docker и тексты его исключений не попадают в отчёт.

## Запуск

Из клона проекта, под владельцем `.env` (мастер обычно создаёт файл под root):

```bash
bash scripts/staging_preflight.sh
```

Нужны Python 3, Git и Docker Compose plugin с поддержкой `config --format json`. Работающий Docker daemon для разбора конфигурации не требуется. Используются `compose.yaml` и, при наличии, `compose.override.yaml`, создаваемый мастером для Caddy. Другие Compose-файлы этим сценарием не проверяются. Флаги Compose и переменные приложения из текущего shell игнорируются: источник настроек — локальный `.env`.

Только конфигурация, без Docker:

```bash
bash scripts/staging_preflight.sh --config-only
```

Машиночитаемый отчёт (значения секретов не включаются):

```bash
bash scripts/staging_preflight.sh --json > staging-preflight.json
```

Код выхода `0` означает успешные проверки выбранного режима, `1` — ошибка. В JSON `scope` определяет режим, `compose_checked` сообщает, выполнен ли вызов Compose; проверяйте также `ok` и пункт `compose`. `--config-only` никогда не подтверждает Compose. При ошибке `.env` или Git Docker не вызывается. Git ограничен 10 секундами, Compose — 20 секундами.

## Исправление ошибок

| Проверка | Что сделать |
|---|---|
| env_file | Убедиться, что `.env` существует, это обычный UTF-8 файл текущего владельца, права 0600 или 0400. Для файла своего пользователя: `chmod 600 .env`. Ссылки не принимаются |
| env_not_tracked | Работать из Git-клона; `.env` не должен быть в индексе. Если секреты уже попали в Git, удалить из индекса недостаточно: отозвать их и заменить |
| required / secrets | Завершить настройку через мастер; использовать разные секреты. Пароль БД и ключ сессии — от 32 символов; BOT_INTERNAL_SECRET — 64 строчных hex |
| database | Согласовать POSTGRES_DB, POSTGRES_USER, POSTGRES_PASSWORD и DATABASE_URL; адрес внутри Compose — db:5432. Спецсимволы пароля в DSN кодируются URL-encoding |
| api_port / project_name | Порт 1024–65535; имя проекта до 63 строчных букв, цифр, дефисов/подчёркиваний, начинается с буквы/цифры |
| telegram | Токен как в BotFather, username без @. Проверка формата не проверяет действительность токена или владельца |
| feature_flags | Использовать только 0/1, не true/false/yes |
| miniapp | При включении нужен HTTPS DNS-домен и путь /miniapp, без query/fragment, userinfo, нестандартного порта |
| sbp_credentials / sbp_webhook | При включённой функции СБП заполнить shop ID, секрет и домен возврата; webhook требует серверной сверки. Сверка может работать при выключенной выдаче новых счетов |
| compose | Проверить Compose plugin и YAML. API должен публиковаться только на 127.0.0.1, БД/бот/worker не публикуют порты; host network и privileged запрещены. Override не должен подменять проверенные параметры и секреты |

Поддерживается простой формат установщика `KEY=value`, пустые значения, комментарии и однострочные значения в одинарных/двойных кавычках. Дубли ключей, shell-подстановки (`$`, обратные кавычки), обратный слеш, escape-последовательности и многострочные значения запрещены. Нестандартный dotenv нужно привести к этому формату; он никогда не исполняется через `source`.

Проверка рассчитана на полный кабинет с ботом. Если в мастере Telegram отложен, обычный запуск выдаст ошибку до его настройки. Явный `--allow-telegram-deferred` разрешает пустые токен и username только при выключенных Mini App, Stars и тестовой среде. Подлинность Telegram при этом не подтверждается. Отдельный классический прокси, установленный через `install.sh`, проверяется по своей инструкции.

Не меняйте пароль существующей БД только в `.env`: это не меняет пароль роли PostgreSQL. Не пересоздавайте ключ сессии без необходимости — старые сессии потеряют доступ. Утилита намеренно ничего не исправляет автоматически.

## Что ещё проверить на стенде

Успешный отчёт не проверяет подключение к БД, назначение администратора, DNS/HTTPS, свободный порт, права Telegram-бота, получение платежей, возврат или показ спонсора. Эти поля в JSON остаются `false`; `release_accepted` всегда `false`.

Следующий этап — [приватный staging](STAGING.md) и [приёмка MVP](MVP_RELEASE_GATE.md). Платёжные флаги не следует включать по одному лишь зелёному preflight. Контрольные тесты с настоящим Compose в GitHub Actions используют искусственные секреты и не запускают контейнеры; отдельный smoke-test проверяет контейнеры и временную PostgreSQL.
