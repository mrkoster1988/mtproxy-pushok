# v1.89 — Возвраты оплаты

Из старого PR #89 перенесён модуль возвратов, адаптированный к текущим платежам, рейтингам и интерфейсу v1.88. Старые миграции не изменены: новые поля и журнал устанавливаются миграцией `063_campaign_refunds.sql`. Остальные старые PR не сливаются этим изменением.

## Действия администратора

В карточке кампании в модерации откройте «Возврат оплаты». Здесь показаны исходная оплата, возвращённая сумма, остаток и история запросов. Укажите сумму и причину, затем подтвердите действие.

| Оплата | Возврат |
| --- | --- |
| Внутренний баланс | Полный или частичный. Сначала бонусы, затем денежная часть; валюты не смешиваются. |
| Telegram Stars | Полный возврат исходному плательщику через `refundStarPayment`. |
| СБП через ЮKassa | Полный или частичный на исходный способ оплаты; минимум 1 ₽, остаток — 0 или от 1 ₽. |
| Оплата, подтверждённая вручную | Только запись возврата, уже выполненного вне кабинета. Требуется отдельная галочка; перевод API не выполняется. |

Запущенное размещение сначала нужно завершить. Будущий слот при запросе возврата отменяется, автоматическое назначение приостанавливается. Незавершённый или выполненный возврат блокирует повторный запуск этой кампании. После частичного возврата платёж остаётся подтверждённым с отдельной суммой возврата; после полного получает статус «Возвращено».

## Повторы и сверка

Намерение фиксируется в БД до сети. Неизменяемые параметры запроса и снимок исходного платежа проверяются при повторе. Блокировки кампании и журнала, уникальные ключи и проверка остатка исключают повторное начисление при одновременных запросах.

Фоновый обработчик платежей проверяет сохранённые и ожидающие запросы. Неопределённый ответ попадает в «Нужна проверка»: администратор использует «Проверить возврат». Если ЮKassa уже выполнила возврат, но ответ потерян, укажите ID из ЮKassa и нажмите «Сверить по ID». Система сверяет ID исходного платежа, сумму, валюту и статус; этот путь выполняет только GET. Неверный ID не сохраняется.

ЮKassa гарантирует идемпотентность 24 часа; повторный POST запрещён уже после 23 часов от первой попытки. При наличии неизвестного внешнего возврата требуется сверка. Для частичного возврата платежа с регистрацией чека сначала оформите возврат с корректным чеком в ЮKassa, затем сверяйте по ID в кабинете. Чек с выдуманным составом не отправляется.

Частичный возврат отзывает реферальную награду один раз и уменьшает расходы текущего рейтинга. Опубликованные итоги закрытых периодов сохраняются.

## Проверки

Регрессии используют отдельную PostgreSQL: частичные и полные возвраты, роли, блокировки, неизменность намерения, одновременные запросы, старый маршрут, баланс, реферальные награды и рейтинг. Вызовы Stars/СБП заменены контролируемым транспортом, включая тайм-ауты, потерю ответа и сверку. Браузерный сценарий работает с настоящими API/SQL и проверяет форму на ширинах 320, 390, 768 и 1280 px.

```bash
python -m unittest discover -s tests -p test_campaign_refunds.py -v
python scripts/check_cabinet_pages.py --refunds-only --out .build/refunds-preview
```

Для тестов требуются отдельная БД и переменные из [политики CI](CI_POLICY.md). Полный workflow дополнительно проверяет остальные сценарии, Compose и Rust. Результат проверки относится к конкретному SHA в [Actions](https://github.com/mrkoster1988/mtproxy-pushok/actions).

Код и тесты не подтверждают установку на рабочий VPS или реальную выплату. Перед приёмкой платного запуска выполните контролируемый возврат в тестовом окружении своего провайдера и сверьте результат в его кабинете. Обновление БД выполняется штатным установщиком с резервной копией.

Официальные ограничения: [Telegram refundStarPayment](https://core.telegram.org/bots/api#refundstarpayment), [возвраты ЮKassa](https://yookassa.ru/developers/payment-acceptance/after-the-payment/refunds), [идемпотентность ЮKassa](https://yookassa.ru/developers/using-api/interaction-format), [чеки возврата](https://yookassa.ru/developers/payment-acceptance/receipts/54fz/other-services/refunds).
