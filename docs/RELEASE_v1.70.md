# v1.70 — Готовность VPS к автосозданию прокси

В настройках владельца «ИИ · Новые прокси» появился блок «Готовность VPS». Хостовый агент проверяет адрес, файлы native MTProxy, постоянные таймеры, сохранённую сессию Telegram, ресурсы, связь с кабинетом, разрешение ИИ, порты и лимит экземпляров. Проблемы показываются одновременно, с понятным следующим действием.

Проверка запускается после каждого прохода агента, в том числе при выключенном автосоздании. Штатный таймер запускает проход через 5 минут после предыдущего; время выполнения добавляется к интервалу. При остановленном таймере новый отчёт не появится: кабинет пометит имеющийся устаревшим через 11 минут. Кнопка «Обновить» читает последний отчёт, не запускает создание.

Перед выдачей задания агент дополнительно проверяет файлы MTProxy и таймеры. Их отсутствие не расходует попытки регистрации. Сверка ранее начатой подготовки сохраняет приоритет и выполняется до этой проверки.

## Проверка на установленном VPS

После штатного обновления проекта и агента:

```bash
sudo python3 /opt/mtproxy-pushok/scripts/proxy_provisioner.py check
```

Команда выводит JSON с фиксированными кодами, обновляет отчёт в кабинете и возвращает `0`, если все предварительные проверки пройдены, `2`, если есть ограничения, или `1` при ошибке самой команды. Выключенное разрешение также даёт `2`: это не поломка установки. Новые прокси и задания не создаются, службы не меняются. Команда не обращается к Telegram или OpenAI.

Если отчёт указывает на таймеры, сначала посмотрите их состояние:

```bash
sudo systemctl status mtproxy-pushok-provisioner.timer mtproxy-pushok-promotion.timer --no-pager
```

Для восстановления штатных таймеров установленного проекта:

```bash
sudo bash /opt/mtproxy-pushok/scripts/install_promotion_agent.sh
```

Это включает существующий агент. При включённой политике он сможет продолжить разрешённую подготовку. Для проблем с файлами MTProxy используйте штатное восстановление установки; проверка сама файлы не заменяет.

## Границы проверки

- Проверяется сохранённая сессия владельца и локальная пауза Telegram. Текущая доступность Telegram без обращения к нему не подтверждается.
- Проверка настроек и очереди выполняется отдельным приватным действием в read-only транзакции PostgreSQL. Нет запросов к модели, выдачи задания, изменения попыток или аудита.
- Занятый лимит и уже начатая подготовка отличаются от конфликта порта. Проверяются публичные порты из заданного диапазона и служебные порты 20000–20002. Это не проверка внешнего firewall.
- Публичный отчёт содержит только фиксированные коды, время и срок паузы. API отбрасывает незнакомые поля и некорректные отчёты. Сессии, телефон, ключи, секреты и сырые ошибки не возвращаются.
- Готовность VPS не равна успешной регистрации нового прокси или фактическому показу спонсора. Эти этапы по-прежнему требуют своих подтверждений.

Миграций БД нет. Политика автосоздания, выбранные лимиты и рабочие узлы сохраняются.

Проверки релиза: PostgreSQL проверяет неизменность очереди и read-only транзакцию; модульные сценарии проверяют сбои файлов, таймеров, ресурсов, портов, паузы и устаревшие отчёты. Chromium проверяет кабинет на ширинах 320/390/768/1280 px. Внешние Telegram, OpenAI и systemd заменяются тестовыми ответами. Живой VPS из среды разработки недоступен; его обновление и запуск здесь не подтверждены.
