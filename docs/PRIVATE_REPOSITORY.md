# Закрытый репозиторий: установка и обновления

Доступ к исходникам назначается в GitHub владельцем `mrkoster1988/mtproxy-pushok`. Клиенты кабинета не нуждаются в доступе к GitHub. Для VPS используйте отдельный fine-grained personal access token с ограниченным сроком действия и единственным выбранным репозиторием `mtproxy-pushok`.

## Права токена

| Repository permission | Доступ | Назначение |
|---|---|---|
| Contents | Read-only | Скачивание исходников и чтение опубликованной версии |
| Actions | Read-only | Проверка CI установленного коммита |
| Metadata | Read-only | Добавляется GitHub автоматически |

Токен создаётся владельцем или пользователем, которому уже предоставлен доступ. Установщику не нужны права записи, Administration или доступ ко всем репозиториям. Токен вводится только в SSH-терминале VPS: не отправляйте его в чат и не добавляйте в URL.

## Уже установленный VPS

Если новая версия уже скачана:

```bash
cd /opt/mtproxy-pushok
sudo bash setup.sh --repository-access
sudo python3 scripts/repository_access.py --check
```

Настройка проверит чтение `release/stable` и результатов Actions, затем сохранит доступ. После этого используйте обычную кнопку обновления. Неверный токен не заменяет сохранённый. После смены токена кэш проверки версии может обновляться до минуты.

Если репозиторий уже закрыт, а на VPS ещё нет этого режима, получите новую версию интерактивно. Сначала сделайте резервную копию по [инструкции](CABINET_BACKUP.md), убедитесь в отсутствии локальных изменений (`git status --short`), затем под root:

```bash
cd /opt/mtproxy-pushok
git -c credential.helper= -c credential.username=x-access-token fetch --no-tags https://github.com/mrkoster1988/mtproxy-pushok.git refs/heads/release/stable
git merge --ff-only FETCH_HEAD
bash setup.sh --repository-access
bash scripts/install_updater.sh
```

В запросе Git `Password` введите токен, затем повторите его в скрытом запросе настройки. Выполняйте команды по очереди и останавливайтесь при ошибке. Если ветки разошлись или есть локальные изменения, не применяйте `reset --hard`: сохраните изменения и разберите расхождение. Последняя команда запускает штатное обновление с резервной копией, сборкой, миграциями и проверкой готовности; во время перезапуска возможна краткая недоступность кабинета.

## Новая установка

Команда и ответы мастера — в [INSTALL_QUICKSTART.md](INSTALL_QUICKSTART.md). Клонирование использует `release/stable`. Анонимные raw-ссылки перестают работать после закрытия GitHub; для отдельного прокси запустите `bash install.sh` из авторизованной копии.

## Хранение и восстановление доступа

- Токен хранится в `.control/github-access-private.json`: файл 0600, каталог 0700, владелец UID/GID 10001 для совместимости с API. Это ограничение доступа к файлу, не шифрование.
- Git config содержит только путь к credential helper; remote URL остаётся без токена. Helper выдаёт данные только для HTTPS и точного репозитория `mrkoster1988/mtproxy-pushok`.
- API использует токен только на сервере для проверки версии и CI. При HTTP-перенаправлении заголовок Authorization не переносится.
- `.control` исключён из Git и Docker build context. Приватные резервные копии включают секретные настройки и требуют соответствующей защиты.
- При истечении срока или отзыве токена повторите `bash setup.sh --repository-access`. Запущенный кабинет продолжит работать; скачать новые версии без доступа не получится.
- После восстановления на другом VPS повторите настройку: локальный Git config с абсолютным путём helper не является переносимой настройкой.

Сделать репозиторий приватным можно в GitHub Settings → General → Change visibility → Make private. GitHub может запросить повторное подтверждение владельца. Наличие этой инструкции или установка v1.89 сами по себе не меняют видимость репозитория.
