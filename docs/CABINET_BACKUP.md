# Резервная копия кабинета и пробное восстановление

Команда дополняет PostgreSQL dump, который установщик создаёт перед миграциями. Она сохраняет **БД, весь стандартный том чеков/доказательств и конфигурацию кабинета** в один приватный комплект.

Поддерживается стандартная Compose-установка проекта, локальный Docker default context и PostgreSQL 16. Пользователь должен иметь доступ к Docker и быть владельцем `.env`; мастер установки обычно работает под root. Понадобятся Python 3, Git, запущенная БД и существующий контейнер API с именованным томом чеков. Нестандартные bind mounts и дополнительные работающие сервисы не принимаются автоматически.

## Одна команда с вариантами ответа

Из каталога проекта:

```bash
sudo python3 scripts/cabinet_backup.py
```

| Выбор | Действие | Что меняется |
|---|---|---|
| 1 или Enter | Показать план | Ничего; Docker не вызывается |
| 2 | Создать копию | Ещё один выбор: 1 — только план, 2 — создать с временной остановкой, 3 — отмена |
| 3 | Проверить комплект | Читаются файлы, размеры, SHA-256 и состав архива; БД не восстанавливается |
| 4 | Пробное восстановление | Создаются отдельная временная PostgreSQL без сети и временный каталог файлов; рабочая БД не меняется |
| 5 | Выход | Ничего |

Для первого использования выберите **1**, затем запланируйте короткое обслуживание и выберите **2 → 2**. Сохраните путь `bundle` из результата. После копирования выберите **3**, укажите этот каталог, затем **4** с тем же каталогом. Передавать токены/пароли в командной строке не нужно.

## Команды без диалога

```bash
sudo python3 scripts/cabinet_backup.py plan
sudo python3 scripts/cabinet_backup.py create --allow-downtime
```

Проверка и пробное восстановление; замените путь на точный `bundle` из результата создания:

```bash
sudo python3 scripts/cabinet_backup.py verify /opt/mtproxy-pushok/.backups/cabinet-ВАШ_ID
sudo python3 scripts/cabinet_backup.py drill /opt/mtproxy-pushok/.backups/cabinet-ВАШ_ID
```

Без `--allow-downtime` команда `create` откажется останавливать работающие API, бота и worker. Блокировка каталога общая с установщиком. Не запускайте параллельно другую копию проекта с тем же Compose-проектом и не меняйте БД вручную во время копирования.

Во время разрешённого обслуживания кабинет временно недоступен, обработка Telegram и платежей приостановлена. БД остаётся запущенной. Возобновляются только те из `api`, `bot`, `sbp-worker`, которые были в состоянии running до операции; выключенный бот не включается. Проверяется возврат состояния контейнеров running, а не живые платежи или Telegram.

## Состав комплекта

Каталог `.backups/cabinet-<случайный ID>/` имеет права 0700; файлы — 0600:

| Файл | Содержимое |
|---|---|
| database.dump | PostgreSQL custom-format dump |
| proofs.tar | Чеки и каталог placement-evidence из стандартного именованного тома |
| config.env | Копия `.env`, включая секреты |
| compose.yaml | Основной Compose |
| compose.override.yaml | Override, если он есть |
| Caddyfile | Конфигурация Caddy, если она есть |
| manifest.json | Версия формата, UTC-время, коммит исходников, размеры/SHA-256, количества записей и файлов |

Комплект **содержит секреты и персональные данные** и не зашифрован. Не публикуйте его в GitHub/чате; для внешнего хранения используйте защищённое хранилище с ограниченным доступом. `.backups/` уже исключён из Git и контекста Docker-сборки. Сохранение на том же диске не защищает от потери VPS: после проверки нужна отдельная защищённая копия.

Не входят: сам код/образы Docker, TLS-ключи и данные томов Caddy, настройки DNS/firewall, отдельный MTProxy/systemd, внешние платёжные системы и сторонние тома. Коммит исходников — ориентир для восстановления кода, а не доказательство версии уже работающего образа. Для нестандартной установки потребуется собственный перечень данных.

## Целостность и согласованность

Сначала блокируется каталог и проверяется доступ к стандартному тому. Затем с разрешения останавливаются сервисы записи, сохраняются БД, файлы и конфигурация. Список dump проверяется через `pg_restore --list`; архив чеков читается в контейнере без сети с томом только для чтения.

Ссылки, устройства, абсолютные пути, `..`, дубли и конфликтующие пути в tar отклоняются. Проверяются права файлов, точный состав комплекта и SHA-256. Лимиты: 20 ГиБ на файл и на распакованные чеки, 100 000 объектов в tar, 1 МиБ на файл конфигурации/манифест. Автоматической ротации старых копий нет.

Запись ведётся в `.incomplete-*`; готовое имя появляется только после проверки комплекта и возобновления исходных сервисов. При обычной ошибке незавершённый комплект удаляется, прежние копии сохраняются. Ручные подключения к PostgreSQL и сторонние процессы не замораживаются: они должны быть остановлены оператором отдельно. SHA-256 выявляет повреждение, но не подтверждает автора копии — изменение и файлов, и манифеста злоумышленником требует отдельной защиты хранилища.

## Что проверяет drill

Нужен локально доступный образ `postgres:16-alpine`. Если его нет, отдельно загрузите его: `docker pull postgres:16-alpine`. Сам `drill` не скачивает образы.

После проверки целостности файлы восстанавливаются в новый приватный временный каталог с проверкой содержимого. БД восстанавливается в новый контейнер PostgreSQL с `--network none`, без опубликованных портов и без подключения рабочих томов. Для локальных соединений внутри этого контейнера используется trust; внешнего сетевого доступа нет. Контейнер ограничен 1 CPU, 1 ГиБ RAM и 128 процессами. Большой restore может потребовать отдельного стенда.

Сверяются количества users, campaigns и payment_attempts. Восстановленный API/бот не запускается, сохранённый `.env` и Compose не исполняются, квитанции/вебхуки не отправляются. Временные файлы и только принадлежащие этой операции контейнеры/anonymous volumes удаляются после проверки. Содержимое БД, чеков, секретов и stderr Docker не выводится.

JSON `ok: true` у `verify` означает целостность, но `database_restored` остаётся false. У успешного `drill` — `database_restored: true`, количество восстановленных файлов и `configuration_executed: false`. `release_accepted` всегда false. Это не проверка входа Telegram, эквайринга, HTTPS или спонсора.

## При ошибке или обрыве

1. Сохранить сообщение об ошибке без раскрытия секретов. Не удалять старые `cabinet-*` и `pre-migration-*.dump`.
2. Проверить `docker compose --profile bot ps`; возобновить только сервисы, которые работали до обслуживания. Не выполнять `down --volumes` на рабочем проекте.
3. Проверить владельца/права, свободное место, локальный Docker, Git и наличие PostgreSQL 16 image.
4. После исправления повторить создание нового комплекта. Повреждённый комплект не править вручную под новый SHA-256.
5. После SIGKILL, падения VPS или питания автоматическая очистка/возобновление не гарантированы: проверить `.incomplete-*` и временные контейнеры с именами `pushok-backup-read-*`/`pushok-restore-*`. Удалять только принадлежащие своей операции ресурсы после проверки меток `io.pushok.backup-read`/`io.pushok.backup-drill`.

Восстановление поверх рабочей установки этой утилитой не поддерживается. Следующий этап приёмки — восстановить реальный комплект на отдельном VPS, затем проверить API, права пользователей, чеки и внешние интеграции по [MVP_RELEASE_GATE.md](MVP_RELEASE_GATE.md).
