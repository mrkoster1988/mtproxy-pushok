# v0.032 — подпись и проверка свидетельств (подготовительный этап)

Модуль `api/app/core_evidence.py` **проверяет** HMAC-SHA256 подписанное свидетельство; он не выпускает подписи и не запускает MTProxy. Источник доказательств, назначение полномочий оператора, хранение ключа и журналирование ещё не реализованы.

Схема receipt v1 содержит: `schema`, `issuer`, `project_version`, `artifact_sha256` (64 строчных hex символа), `issued_at` и `expires_at` (Unix UTC), `checks` со всеми шестью булевыми gate из `core_acceptance.GATES`. Envelope: `{"receipt": {...}, "signature": "<hex HMAC SHA256>" }`. Подписываются канонические JSON-байты (sorted keys, separators без пробелов, UTF-8, no NaN).

Валидация отказывает при неверной подписи, неизвестном issuer, неправильной версии или контрольной сумме, просрочке, сроке более суток, будущем времени выдачи более чем на 60 секунд, некорректных типах, отсутствующем gate и слабом ключе менее 32 байт.

**Безопасность:** корректная подпись доказывает лишь, что сторона, знающая ключ, подписала указанные флаги. Она **не** подтверждает реальную работу Telegram или наличие рекламного канала. До подготовки уполномоченного issuer, доверенного сбора данных, хранения ключей и аудита любое значение `ready_for_production` из этого модуля остается только оценкой переданных данных.

## Проверки

```bash
python3 -m unittest discover -s tests -p 'test_core_evidence.py' -v
```

Локальные unit-тесты выполняются без сетевых вызовов. Проверка CI и staging необходима отдельно. На VPS ничего не разворачивается. Ни VPN, ни RemnaShop не подключаются.
