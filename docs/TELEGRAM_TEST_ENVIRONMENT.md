# Отдельный стенд Telegram Test Environment

Это проверка интеграции с тестовым Telegram, а не имитация оплаты в браузере.
Основной бот, рабочая БД и реальные Stars для неё не используются.

## Подготовка

1. Создайте отдельную установку проекта: отдельный каталог, Docker Compose project,
   БД/тома, HTTPS-домен, SESSION_SIGNING_KEY и BOT_INTERNAL_SECRET. Не подключайте
   её к рабочим MTProxy-узлам, СБП или боевой базе. Домен Mini App должен открываться
   тестировщику; HTTPS остаётся обязательным в Pushok даже в тестовом режиме.
2. В Telegram Desktop откройте Settings, затем Shift + Alt + правый клик по
   Add Account → Test Server. Зарегистрируйте отдельный тестовый аккаунт.
3. Через @BotFather именно в тестовой среде создайте нового бота. Его токен и
   username отличаются от рабочего бота. Создайте тестовый публичный канал и
   назначьте тестового бота администратором. Владелец заявки тоже должен иметь
   подтверждаемые права администратора канала.
4. Укажите в `.env` тестовой установки:

   ```dotenv
   PUSHOK_TELEGRAM_TEST_ENVIRONMENT=1
   TELEGRAM_BOT_TOKEN=REPLACE_WITH_TEST_BOT_TOKEN
   TELEGRAM_BOT_USERNAME=REPLACE_WITH_TEST_BOT_USERNAME
   PUSHOK_MINIAPP_ENABLED=1
   PUSHOK_MINIAPP_URL=https://REPLACE_WITH_TEST_DOMAIN/miniapp
   PUSHOK_STARS_PAYMENTS_ENABLED=1
   PUSHOK_SBP_PAYMENTS_ENABLED=0
   PUSHOK_SBP_RECONCILIATION_ENABLED=0
   PUSHOK_SBP_WEBHOOK_ENABLED=0
   ```

   Значения REPLACE замените до запуска; токены не публикуйте. Создайте пользователя
   оператора средствами проекта. Настройте отдельную цену Stars в тарифе.
5. Примените миграции штатным установщиком (включая 021), затем запустите отдельный
   Compose project с профилем bot. Обновляя уже запущенный тестовый стенд, пересоздайте
   API и bot после изменения `.env`: оба процесса должны видеть одинаковый режим.
   Для ручного обновления БД из корня тестовой установки:

   ```bash
   docker compose exec -T db sh -c 'psql -v ON_ERROR_STOP=1 -U "$POSTGRES_USER" -d "$POSTGRES_DB"' < database/021_telegram_test_environment.sql
   docker compose --profile bot up -d --build api bot
   ```

   Если используется `-p` или COMPOSE_PROJECT_NAME, сохраняйте имя тестового проекта
   во всех командах. Не выполняйте эти команды из каталога рабочей установки.

## Приёмка

- Откройте тестового бота в тестовом Telegram, нажмите «Открыть Mini App».
  Проверьте вход, права пользователя и оформление на телефоне.
- Создайте заявку с тестовым каналом. Оператор одобряет её. В оплате должна быть
  надпись «Тестовая среда Telegram · тестовые Stars» и правильная сумма XTR.
- Откройте счёт, отмените: API остаётся awaiting_payment. Повторное открытие
  возвращает тот же ожидающий счёт, а не создаёт второй.
- Пройдите тестовую оплату средствами тестового Telegram. Убедитесь, что бот
  получает pre_checkout_query и successful_payment. Только после серверной
  проверки статус становится verified. Повтор receipt не создаёт вторую оплату.
- Отключение выдачи новых счетов не должно потерять уже полученную квитанцию.
  После оплаты размещение остаётся отдельным этапом: verified не означает,
  что sponsor-tag уже применён к работающему MTProxy.
- Зафиксируйте результат и ошибки без токенов/initData. Отдельно проверьте
  основную среду и реальное назначение спонсора перед включением приёма в production.

## Граница сред

По умолчанию PUSHOK_TELEGRAM_TEST_ENVIRONMENT=0. При 1 все Bot API вызовы бота,
проверки каналов и createInvoiceLink идут на фиксированный адрес
`https://api.telegram.org/bot<TOKEN>/test/METHOD`. Произвольный API host не задаётся.
Неверное значение флага останавливает вызов, без перехода на основную среду.

Каждая новая Stars-попытка сохраняет среду до обращения к Telegram; старые попытки
считаются production. Действующий счёт из другой среды не переиспользуется;
precheckout не одобряется, несовпадающая квитанция требует ручного разбора.
Внутренние Stars-запросы бота несут заголовок среды. Тестовый API требует test;
основной принимает production (также отсутствие заголовка для старого бота).
Это дополнительная защита, а не разрешение использовать общую БД. Не переключайте
рабочую установку в тестовый режим и не меняйте сохранённую среду попыток вручную.

Локальные/CI тесты используют подставной транспорт и временную БД. Их прохождение
не доказывает живую оплату, доступность клиента Telegram или запуск спонсорства.

Официальная инструкция Telegram:
https://core.telegram.org/bots/webapps#using-bots-in-the-test-environment
