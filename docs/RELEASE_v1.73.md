# v1.73 — Согласованная диагностика автосоздания

Ручная проверка могла завершиться успешно, а запущенная раньше медленная проверка по расписанию позднее заменяла её отчётом с ошибкой. Кроме того, общий обработчик называл ошибку локального порта потерей связи с базой.

Публикация теперь сравнивает время начала проверок под общей файловой блокировкой. Поздно завершившийся старый проход не заменяет более новый результат. Настоящий сбой нового прохода сохраняется. Файл доступен пользователю API сразу при атомарной замене.

Чтение настроек использует общую блокировку с обновлятором: во время обслуживания проверка сообщает о занятости и повторяется по обычному расписанию. Тайм-аут и некорректный ответ кабинета имеют отдельные коды. Ошибка локального порта не отменяет успешного чтения настроек. Тексты команд, stderr и секреты в публичный отчёт не попадают.

В кабинете указан источник отчёта: ручная проверка или расписание. Неудачное получение настроек больше не выглядит как ожидание новой версии разрешений. Проверка версии настроек из v1.72 и срок давности остаются в силе.

Обновлять нужно кабинет и хостовый агент штатным обновлением проекта. Миграций нет. Следующий проход таймера обновит отчёт. Кнопка «Обновить» читает результат, не создаёт прокси и не обращается в Telegram или к ИИ. Ручной безопасный запуск:

```bash
sudo python3 /opt/mtproxy-pushok/scripts/proxy_provisioner.py check
```

Успех предварительной проверки не подтверждает создание экземпляра, регистрацию в Telegram или фактический показ спонсора. Причину конкретного сбоя на VPS нельзя установить только по двум противоречащим скриншотам; исправлены воспроизводимые ошибки сохранения и классификации диагностики.
