# v0.032 — формальные критерии приёмки Pushok Core (кандидат)

Это **не релиз и не факт прохождения проверок на VPS**. Модуль `api/app/core_acceptance.py` принимает доказательства от отдельного контролируемого проверяющего процесса и возвращает список незакрытых пунктов. Никаких команд на сервере, сетевых вызовов и переключений сервисов он не делает.

## Обязательные критерии

1. `artifact` — источник, SHA256 и лицензионные уведомления.
2. `isolated_tcp` — успешный офлайн TCP smoke в контейнере.
3. `valid_handshake` — корректный MTProxy handshake на отдельном staging.
4. `telegram_client` — реальное подключение клиента Telegram на staging.
5. `sponsor_delivery` — ручная проверка отображения нужного спонсорского канала.
6. `rollback` — проверенный возврат рабочей службы на тестовом узле.

Пустые или не-булевы доказательства означают **не пройдено**. Офлайн CI не вправе сам подтверждать пункты 3–6. Значение `ready_for_production=true` означает лишь, что все входные флаги переданы как true, а **не** то, что модуль самостоятельно удостоверил их достоверность. Для реального допуска понадобится независимая аттестация источника доказательств.

## Локальная проверка

```bash
python3 -m unittest discover -s tests -p 'test_core_acceptance.py' -v
```
