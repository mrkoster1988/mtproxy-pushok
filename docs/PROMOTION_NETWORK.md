# Pushok Promotion Network — этап разработки (ветка feature/pushok-promotion-network)

## Назначение

Один существующий MTProxy Pushok, один бот и одна панель. Разные MTProxy-узлы
содержатся в общем реестре. В свободных временных окнах узла планируется
собственный канал `https://t.me/pushok_proxy`, а в оплаченных и одобренных
окнах — канал рекламодателя. Базовый тариф сохраняется: **1 день — 300 ₽**.

Результат — **план переключения**, а не само переключение и не платёжный чек.
Настоящий показ требует настройки `@MTProxyBot → /myproxies → Set promotion`
и проверки с независимого Telegram-клиента, не подписанного на канал.

## Реализовано в ветке

- `GET /api/v1/admin/network/promotion-plan` — план сети на текущий момент;
  `?at=2026-11-15T12:00:00+00:00` — план на указанное время.
- Доступ только роли admin, без показа MTProxy tag/secret, с `Cache-Control: no-store`.
- Приоритет коммерческих слотов над своим каналом. Нет оплаченного размещения
  — узел рекомендует собственный канал; остановленный узел и отсутствие тега
  — блокирующие состояния; конфликт коммерческих периодов — аварийное состояние.
- Отдельный read-only блок в админской панели для проверки узлов и действий.
- Не подменяет существующий календарь, БД-ограничения, бронь, модерацию и
  ручной учёт платежей. Не обращается к серверу и Telegram.

## Дальнейшая реализация перед промышленным запуском

1. На отдельном тестовом VPS провести реальную регистрацию и испытание хотя бы
   одного прокси с публичным каналом Pushok. Сохранить скриншоты и журнал.
2. Создать приватные выдаваемые ссылки подключения и измерение агрегированных
   подключений по узлам без записи пользовательских чатов и IP в аналитику.
3. Подключить реальный провайдер платежей с проверяемыми webhook,
   идемпотентностью и сопоставлением транзакции с кампанией.
4. Исследовать подтверждённый способ надёжно переключать спонсора, с
   откатом, мониторингом и тестовым узлом. Не использовать неофициальный
   Telegram userbot для обхода отсутствующего API без отдельной оценки рисков.
5. Завершить CI/staging проверку до выпуска в main или применения на VPS.
