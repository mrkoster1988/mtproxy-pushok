# v0.057 — права исходников после обновления

Служба обновления работает с UMask=0077 для защиты резервных копий и секретов. Git может создать изменённые файлы кода с правами 0600 и каталоги 0700. В v0.056 Docker копировал эти права в образ, где API и бот работают под UID 10001. Результат: PermissionError при импорте main.py и перезапуск контейнеров; локальный API не готов.

В v0.057 Docker-сборка нормализует права только скопированного кода и веб-статики: каталоги 0755, файлы 0644. Владелец кода остаётся root, исполнение — UID 10001. Маска обновлятора, .env, резервные копии, чеки и volume навигации не открываются.

Установить можно штатной кнопкой после восстановления кабинета. Если кабинет v0.056 не запускается, выполните от root:

```bash
cd /opt/mtproxy-pushok
chmod -R a+rX api/app api/web bot
docker compose --profile bot build api bot sbp-worker
docker compose --profile bot up -d --no-deps api bot sbp-worker
python3 scripts/installer_runtime.py wait-api
```

Затем откройте кабинет и установите v0.057 штатной кнопкой. Обновлятор повторно проверит резервное копирование, миграции, готовность API и настройку MTProxy. Изменение прав исходников не меняет содержимое отслеживаемых файлов Git. Не применяйте chmod ко всему /opt/mtproxy-pushok.

Проверки CI собирают образы из отдельной копии с правами 0600/0700, импортируют API/бота под UID 10001 без сети и проверяют запись SQLite в отдельный volume с правами 0700/0600. Эти проверки не подтверждают работу Telegram на VPS — после установки отправьте /start и проверьте передачу сообщений.
