## [1.09] — администраторы, навигация и автоматическое завершение

- Боковое меню и кнопка «Меню» удалены. Навигация на всех экранах: нижняя панель и раздел «Профиль».
- В «Настройки → Система» можно добавлять администраторов/операторов и снимать права по Telegram ID зарегистрированного пользователя. Изменения записываются в аудит, старые сессии завершаются; нельзя снять права с себя или удалить последнего администратора.
- Агент автоматически завершает истёкшую кампанию после успешного снятия/смены тега, в том числе при переключении спонсоров. Ошибка агента не считается завершением.
- Автоподбор назначает только подготовленные узлы с действующей привязкой тега канала.
- Ручные формы назначения, проверки и завершения спрятаны в дополнительные действия; основной сценарий автоматический.
- Статусы в основных разделах обновляются автоматически. События автоматического цикла включены в отчёт.
- [Аудит оставшихся первичных настроек и исключений](AUTOMATION_AUDIT.md).

После установки миграции 031 автоматическое завершение выполняется агентом. Для нового администратора: сначала вход в кабинет, затем назначение роли по Telegram ID; бот должен быть запущен для получения уведомлений.

## [1.08] — автоматический статус запуска кампании

После успешного применения спонсорского тега и подтверждения работающего процесса агент переводит текущую оплаченную и одобренную кампанию из «Запланировано» в «Активно». Ручная визуальная проверка показа не требуется для этого перехода и остаётся отдельным результатом наблюдения.

Повторный ответ агента не дублирует событие запуска. Ответ для устаревшего плана не активирует заявку. Само наступление времени начала не считается успешным запуском.

После установки исправление применяется на следующем успешном цикле агента, в том числе к уже запущенной кампании в текущем периоде. Автоматическое завершение этим выпуском не меняется.

## [1.04] — готовность по результатам приёмки

- Вместо неизменного итога — отдельный прогресс бесплатного пилота и платного запуска.
- Последняя проверка показа на активном узле учитывается с датой, кампанией и источником; отрицательное наблюдение не выдаётся за неисправное подключение.
- Полный цикл требует положительного наблюдения, активации и явного подтверждения прекращения показа той же кампании.
- Администратор записывает результаты реальных испытаний Stars, СБП и восстановления; история хранится в аудите. Повтор запроса не создаёт дубликат, новый неуспешный отчёт отменяет прежний успешный.
- История приёмки сохраняет дату и версию испытания после обновлений. Новые отчёты принимаются за последние 7 дней. Это приёмка по записям, не мониторинг всех узлов.
- Экспериментальное Pushok Source Core отделено от работающего MTProxy Classic. Проверка файлов скриншотов перенесена в блок готовности.
- Сводка не включает оплату, не переключает прокси и не публикует кабинет. Для контрольной кампании добавлена инструкция.

## [0.065] — согласованная диагностика применения тега

- Карточка узла учитывает свежий отчёт агента, подтверждение в БД и текущий план: после успешной сверки больше не предлагает ждать уже полученного подтверждения.

- План кампании, применение тега и фактический показ канала остаются отдельными состояниями. Устаревший, чужой или ошибочный отчёт не подтверждает применение.
- Добавлена отдельная ручная проверка ответа Telegram через действующий MTProxy: [инструкция](docs/TELEGRAM_PROMO_PROBE.md). Пользовательская сессия хранится в памяти и завершается после проверки.
- Схема БД, параметры MTProxy и расписание агента не меняются.

## [0.064] — подтверждение по последнему отчёту агента

- В настройках тарифа кнопки «Сохранить» и «Удалить» стали компактнее и расположены в одну строку, с одинаковой высотой и промежутком.
- Карточка кампании и список автоприменения сверяют запись БД со свежим успешным отчётом агента для того же узла и той же ревизии плана.
- Новая ошибка или возврат исходного тега отменяют прежнее подтверждение. Отсутствующий, старый, некорректный или чужой отчёт не подтверждает применение.
- Агент добавляет в приватный отчёт идентификатор узла и ревизию плана; полные теги, секреты и ревизия не выдаются через HTTP API.
- После обновления старый отчёт без этих полей требует новой проверки агента. Схема БД и условия выбора кампании не меняются.

## [0.063] — восстановление после сбоя смены спонсора

- Неудачное применение нового тега возвращает исходный тег узла. Предыдущий рекламный тег больше не остаётся со сроком новой кампании.
- Незавершённая попытка сохраняется до подтверждённого восстановления: повтор выполняется перед обращением к кабинету и ожиданием обновлятора.
- Старые state-файлы поддерживаются. Успешно применённый тег остаётся до своего срока при временной недоступности API; секрет подключения не меняется.
- Добавлены проверки отказа нового тега, повторного отказа восстановления, прерывания агента, ошибки записи и занятого обновлятора. Реальный показ Telegram проверяется отдельно.

## [0.062] — достоверное подтверждение применения спонсорского тега

- Подтверждение агента связано с конкретным планом. После отмены, переноса периода, смены тега, паузы узла или изменения условий кампании старый ответ больше не показывает «тег применён».
- Кабинет рекламодателя и список узлов используют одинаковую серверную проверку; дата из будущего не считается свежим ответом.
- Агент проверяет активность службы и TCP даже при совпадении тега. Недоступную службу пробует перезапустить; без успешной проверки не отправляет подтверждение.
- Миграция 028 добавляет отпечаток плана. Старые записи требуют нового ответа агента; теги и отпечатки не публикуются в HTTP API.
- Сохранены дизайн Mini App и диагностика домена/IP из v0.061. Проверка службы не означает подтверждения показа канала в Telegram.

- В разделе «Спонсоры и узлы» добавлена диагностика готовности кампании и последнего ответа агента с причинами остановки. Регистрация тега и планирование движка не обозначаются как фактический показ в Telegram.

- Исправлена проверка пустого кабинета после перехода с таблиц на карточки. Браузерный сценарий проверяет десять экранов Mini App в двух мобильных размерах и сохраняет отдельные снимки.

## [0.060] — восстановление обновлений после удаления образа API

- Копирование чеков использует локальный образ PostgreSQL, если старый образ API уже удалён. Образ фиксируется по SHA до остановки сервисов; загрузка и сборка при копировании не выполняются.
- При отсутствии обоих образов проверка останавливается до простоя кабинета.
- Миниапп показывает этап сбоя обновления: копия, сборка, база, перезапуск, API или прокси.
- Назначение и перенос слота запрещены раньше желаемого начала заявки.
- Добавлены регрессии удалённого образа и проверка полного backup/restore в Compose.

## [0.059] — автоприменение подготовленных спонсорских тегов

- Связь узла и канала с тегом, заранее настроенным в @MTProxyBot, доступна администратору.
- Локальный systemd-агент применяет тег в пределах слота и возвращает исходный после окончания/отмены.
- Нет команд или путей из БД: разрешён только 32-символьный hex-тег, фиксированная служба MTProxy Classic.
- Неуспешный перезапуск возвращает исходный файл; срок хранится на VPS для восстановления при сбое API.
- Статус применения конфигурации отделён от подтверждения фактического показа Telegram.
- Автоподбор предпочитает узлы с подготовленной связью для канала. Пустой список узлов объясняет, что сделать.
- Смена Set promotion в Telegram не автоматизирована. Подготовка связи выполняется один раз администратором.
