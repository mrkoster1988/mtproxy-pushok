# История изменений MTProxy Pushok

## [0.018] — 2026-11-08 (код, CI ожидается)

- Очередь `/moderation` в Telegram: до пяти ожидающих заявок, кнопки одобрения, возврата на доработку и отказа; для двух последних обязателен текстовый комментарий.
- Внутренние API проверяют `operator/admin` в БД на каждом обращении, не полагаются на клиентский Telegram ID как на самостоятельное право доступа. Смена статуса выполняется условным SQL UPDATE, решение записывается в audit_events.
- `/history` показывает до 10 последних собственных решений оператора.
- Опциональные уведомления о новых ожидающих заявках владельцу: `BOT_OPERATOR_TELEGRAM_ID`, таблица `bot_operator_notifications` с отметкой только после успешного sendMessage; возможна повторная доставка после ошибки ACK.
- Установщик применяет новую повторяемую миграцию без удаления существующих данных. Добавлены unit- и интеграционные тесты с PostgreSQL.
- **Сервер не менялся, Telegram-бот не развёрнут, платежи и реальное переключение спонсора не автоматизированы.**

## [0.017] — 2026-11-08 (код проверен CI; развёртывание ожидается)

- После создания черновика появилась кнопка проверки Telegram-канала и отправки на модерацию.
- Используются официальные Bot API `getMe`, `getChat`, `getChatMember` для проверки: правильный бот, публичный канал, бот-администратор, рекламодатель-администратор.
- Секретный внутренний endpoint принимает только собственные черновики. Проверка прав выполняется до изменения статуса; номер канала сохраняется, статус становится `pending`, событие записывается в аудит.
- Повторное подтверждение статуса `pending` идемпотентно и не вызывает повторную запись аудита. Чужие заявки и неподходящие статусы отклоняются.
- GitHub Actions: **90 Python-тестов и Docker Compose smoke-test успешны** (PR #2). Сервер и действующий бот не изменялись.

## [0.016] — 2026-11-08 (код проверен CI, развёртывание ожидается)

- В Telegram-боте добавлен двухшаговый мастер оформления черновика: ссылка публичного канала, подтверждение тарифа 1 день — 300 ₽.
- Добавлен закрытый API создания черновика с проверкой секрета, Telegram ID, формата публичного канала и строго заданного тарифа из БД. Оплата и реальное размещение не запускаются.
- В PostgreSQL добавлен необязательный UUID-ключ запроса и уникальный индекс: повторное подтверждение возвращает прежнюю кампанию, а не создаёт повтор.
- При создании черновика создаются учётная запись Telegram и канал в рамках существующей схемы пользователей/каналов; существующие записи не перезаписываются.
- `setup.sh` применяет идемпотентную миграцию к существующим инсталляциям; добавлены тесты мастера, приватности и повторов.
- Состояние ввода хранится в памяти единственного polling-процесса 10 минут; не заявляется как устойчивое хранение.
- GitHub Actions PR #1: 64 теста и Compose smoke успешно пройдены. Публикация, модерация, Telegram Stars, автоматическое управление MTProxy и реальный запуск на VPS ещё не проверены.

## [0.015] — 2026-11-08 (код, приёмка ожидается)

- Внутренний read-only маршрут API для последних десяти кампаний, отфильтрованных по подтверждённому Telegram user ID.
- Доступ к API защищён независимым случайным 256-битным секретом; отсутствующий, ошибочный или шаблонный секрет отклоняется до обращения к БД.
- Кнопка «Мои кампании» и /campaigns получают данные только при совпадении sender ID и private chat ID; при сбое показывается безопасное сообщение.
- Бот подключён к API отдельной закрытой Docker-сетью, без доступа к сети PostgreSQL; секрет генерируется установщиком для новых конфигураций.
- Добавлены тесты приватности, отказа без секрета, успешной выборки, кнопок и ошибок API. Результат CI и реальная работа на VPS пока не подтверждены.
- Оплата Stars, создание заявок через бот, управление прокси и реальный запуск остаются следующими этапами.

## [0.014] — 2026-11-08 (код, приёмка ожидается)

- Создан отдельный необязательный Docker Compose-профиль для Telegram-бота; он не запускается при обычном развёртывании кабинета.
- Бот работает без root, с read-only filesystem и отдельной исходящей сетью, без доступа к PostgreSQL/API.
- На старте проверяются username бота и отсутствие webhook; ошибку не исправляем автоматически и не выводим токен в логи.
- Исправлен порядок подтверждения Telegram updates после обработки; добавлены тесты конфликта webhook, неправильного токена и изоляции контейнера.
- Добавлена инструкция безопасного запуска. Не проведена реальная проверка на VPS, платежи и рекламные кампании через бота пока не реализованы.
