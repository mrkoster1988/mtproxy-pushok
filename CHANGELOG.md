# История изменений MTProxy Pushok

## [Unreleased] — атомарное подтверждение Telegram Stars (11 ноября 2026)

- Обработчики Stars `precheckout` и `settle` теперь требуют реально обновлённую строку PostgreSQL через `UPDATE ... RETURNING id`.
- Платёж не помечается применённым и не попадает в успешный аудит, если не обновилась попытка или кампания: ошибка 503 откатывает транзакцию и позволяет повторно доставить Telegram update.
- Добавлены негативные API-тесты на отсутствие обновлённой строки. Это не включает настоящую оплату Stars до тестового Bot API и отдельной коммерческой приёмки.



## [Unreleased] — имя Telegram-бота из мастера (11 ноября 2026)

- Служба бота получает `TELEGRAM_BOT_USERNAME` из Docker Compose и проверяет через `getMe` именно настроенное имя; если переменная не установлена — совместимый default `mtproxy_pushok_bot`.
- Команды вида `/start@botname` сверяются с тем же настроенным именем. Мастер проверяет длину username (5–32 символа).
- Добавлены тесты собственного username, чужих упоминаний и ошибочной конфигурации; нет запуска Telegram или изменения работающего VPS.



## [Unreleased] — изоляция портов приватного стенда (11 ноября 2026)

- Предпусковая проверка анализирует объединённый Docker Compose JSON, включая override: допускает только один loopback-порт API 8000, блокирует публичные порты, host-network и privileged сервисы.
- Добавлены негативные тесты публичного API, дополнительных опубликованных сервисов, host network и отсутствия loopback API.
- Вывод Compose JSON не публикуется из-за возможных секретов; это offline gate, не доказательство запуска.


## [Unreleased] — изоляция приватного стенда (11 ноября 2026)

- Предпусковая проверка запрещает внешнюю/чужую PostgreSQL и несовпадение DB учётных данных с Compose, не раскрывая реквизиты.
- Требует закрытых прав на `.env` и выключенных Stars-счетов в приватном staging, предотвращая случайный коммерческий запуск.
- Добавлены негативные тесты на чужую БД, неправильный пароль, слабые права и включённый биллинг; без Docker/VPS.


## [Unreleased] — проверка приватного staging без Telegram-токена (11 ноября 2026)

- `scripts/staging_preflight.sh` принимает два явных режима: `--cabinet-only` (по умолчанию, без бота) и `--with-bot` (с обязательными Telegram-токеном/username).
- Проверка Compose теперь соответствует выбранному профилю и не требует настройки бота для изолированного веб-кабинета.
- Добавлены локальные тесты на временной конфигурации с подменённой командой Docker; реальный VPS/Telegram не проверяются.


## [Unreleased] — защита транзакционной сверки СБП (11 ноября 2026)

- `reconcile_sbp_attempt` требует подтверждённую обновлённую строку `payment_attempts` через `UPDATE ... RETURNING id`; отсутствие строки вызывает `attempt_changed`, до записи аудита. Вызывающая сторона обязана откатить транзакцию.
- Добавлен отрицательный pytest-тест для нулевого обновления попытки. Это не подключает webhook, боевой эквайринг или автоматическую оплату; необходима проверка CI.


## [Unreleased] — отрицательное наблюдение при снятии рекламы (11 ноября 2026)

- При `active` можно записать наблюдение после конца планового слота, но не после завершения.
- Завершение требует последнего свежего отрицательного наблюдения **после** активации плюс двух ручных подтверждений.
- Добавлены unit/PostgreSQL-тесты, кнопка кабинета и инструкция. Это не автоматическое управление Telegram.


## [Unreleased] — безопасное завершение платного слота (11 ноября 2026)

- Завершение требует отдельных подтверждений снятия платного спонсора и восстановления собственного канала Pushok.
- Аудит обозначает `source=operator_attestation`, `telegram_api_verified=false` — никаких заявлений о независимом Telegram API-подтверждении.
- Добавлены негативные unit/real PostgreSQL-тесты и обновлены операторские шаги в кабинете и инструкции.
- Не выполняет автоматического переключения, платежей или операций на VPS; только GitHub Draft PR.


## [Unreleased] — единый GitHub-процесс (11 ноября 2026)

- Отменена обязательная проверка стороннего CI в offline preflight и удалена его конфигурация; GitHub Actions остаётся единственным CI/CD.
- Обновлены правила приёмки, дорожная карта и предупреждения о стенде. Исторические записи сохранены как история, не как действующий процесс.
- Нет изменения API, работающего MTProxy, Telegram, СБП или Stars; PR #23 остаётся Draft до стенда и CI на новом SHA.

## [Unreleased] — интеграционный контракт спонсорских слотов (10 ноября 2026)

- Согласованы проверки `target_engine` и `registration_engine`: при несовпадении зарегистрированного тега план сети блокирует предложение платного и собственного канала.
- Исправлен интеграционный тест для валидного совпадающего движка и тега. Отдельные отрицательные тесты проверяют блокировку несовпадения.
- Не включает автоматическую смену спонсоров, реальные платежи или изменение VPS. Слияние только после полного CI.


## [Unreleased] — восстановление CI (11 ноября 2026)

- Исправлены pytest-сценарии управляющих символов в СБП URL и проверка dry-run, ошибочно трактовавшая `SELECT FOR UPDATE` как запись.

- По реальным GitHub Actions логам исправлены устаревшие mocks Stars API (добавленные SQL-запросы pre-checkout/receipt) и тест project_version привязан к версии запущенного FastAPI вместо исторического `0.031`.

- Перемещён `require_admin` до первого использования в декораторах FastAPI; права администраторов сохранены.
- Добавлен pytest как test dependency и отдельный запуск pytest-native проверок платежей и фонового обслуживания.
- Обновлён контракт теста HTML для существующей формы редактирования тарифов, сохранив обязательные прежние формы.
- После восстановления GitHub hosted runners ошибки подтверждены по журналам; успешность CI на новом SHA требует проверки.

## [Unreleased] — сверка платежей СБП

- Добавлен `api/app/sbp_reconcile.py`: серверная транзакционная сверка сохранённой попытки через авторитетный GET к ЮKassa, блокировка строк заказа и попытки, строгое сравнение суммы/валюты/кампании и идемпотентная обработка повторного события.
- Добавлены негативные unit-тесты для чужой кампании, неправильной суммы, незавершённого платежа, повторной доставки и недопустимого состояния заявки.
- Интеграция **ещё не подключена** к HTTP webhook/кнопке оплаты; сборка, PostgreSQL и CI на актуальном SHA не подтверждены; боевые оплаты отключены. Для корректного commit/rollback вызывающая сторона обязана использовать транзакцию.

## [Unreleased] — безопасность СБП

- Усилена структурная проверка ссылки эквайринга перед перенаправлением пользователя: HTTPS, hostname, запрет credentials, нестандартного порта, фрагмента и управляющих символов.
- Добавлены регрессионные тесты подозрительных ссылок; реальные платежи и полноценная CI-приёмка не подтверждены.
